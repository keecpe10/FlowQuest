# ออกจากระบบอัตโนมัติเมื่อไม่มีการใช้งาน ปิดเบราว์เซอร์ หรือปิดเครื่อง

วันที่ 8 กันยายน 2569

## ปัญหา

ตอนนี้ผู้ใช้ยังคงล็อกอินค้างอยู่แม้จะเดินจากไป ปิดเบราว์เซอร์ หรือปิดเครื่อง
เพราะสองอย่างประกอบกัน

- `backend/routes.py:14` ตั้ง `TOKEN_LIFETIME = timedelta(days=1)` token จึงใช้ได้อีก
  หนึ่งวันเต็มไม่ว่าเจ้าของจะทำอะไรอยู่
- `frontend/src/store/useAuthStore.ts:22` เก็บ token ไว้ใน `localStorage` ซึ่งอยู่ข้าม
  การปิดเบราว์เซอร์และการปิดเครื่อง เปิดกลับมาก็ยังอยู่ในระบบ

ในห้องเรียนที่ใช้เครื่องร่วมกัน คนถัดไปที่เปิดเบราว์เซอร์จะได้บัญชีของคนก่อนหน้าไปเลย

## เป้าหมาย

1. ไม่มีการใช้งาน 30 นาที ให้ออกจากระบบ โดยเตือนล่วงหน้า 1 นาที
2. ปิดเบราว์เซอร์แล้วเปิดใหม่ ต้องเจอหน้าล็อกอิน
3. ปิดเครื่องแล้วเปิดใหม่ ต้องเจอหน้าล็อกอิน
4. กด F5 ต้องไม่หลุด และเปิดหลายแท็บพร้อมกันต้องไม่รบกวนกัน

## ขอบเขตที่ไม่ทำ

- ไม่แตะกติกา "หนึ่งบัญชีล็อกอินได้ทีละเครื่อง" ที่มีอยู่ ต้องทำงานเหมือนเดิมทุกประการ
- ไม่ไล่ใส่เหตุผลของ 401 ในทั้ง 115 จุดที่เรียก `get_current_user_id` ฝั่ง backend
- ไม่ยิง `sendBeacon` ตอนปิดแท็บ (ดูหัวข้อ "ทางที่ตัดออก")

## ข้อจำกัดที่ยอมรับ

การปิดเครื่องแบบดับกะทันหันหรือถอดปลั๊ก เบราว์เซอร์ไม่ทันส่งอะไรออกมา เซิร์ฟเวอร์จึง
ตัดรอบนั้นได้เร็วที่สุดที่ 30 นาทีนับจากกิจกรรมสุดท้าย ไม่มีวิธีทำให้ "ทันที" จริงได้
แต่ผู้ใช้ที่เปิดเครื่องกลับมาจะเจอหน้าล็อกอินทันที เพราะ token หายไปพร้อม `sessionStorage`
ช่องว่างที่เหลือจึงจำกัดอยู่แค่กรณีที่มีคนคัดลอก token ออกไปก่อนหน้านั้น และกินเวลา
ไม่เกิน 30 นาที

## สถาปัตยกรรม

การหมดอายุจริงบังคับที่ `exp` ของ JWT ฝั่งเซิร์ฟเวอร์ ส่วนหน้าเว็บมีหน้าที่สองอย่าง
คือ ต่ออายุ token ให้เมื่อผู้ใช้ยังใช้งานอยู่ และทิ้ง token เมื่อปิดเบราว์เซอร์

```
กิจกรรมของผู้ใช้ ──► ตัวนับ idle ────► เตือนที่ 29 นาที ──► ตัดที่ 30 นาที
       │
       └──────────► token อายุเกิน 15 นาที ──► POST /auth/refresh ──► exp ขยับ
                                                          │
                                              กระจาย token ใหม่ทุกแท็บ

ไม่มีกิจกรรม ──► ไม่มีใครเรียก refresh ──► exp ผ่านไป ──► ทุก request ตอบ 401
```

เลือกบังคับที่ `exp` แทนการทำ sliding TTL ใน Redis เพราะ `auth_utils.user_id_from_token`
ตั้งกติกาไว้ว่า "ไม่มีค่าเก็บไว้ใน Redis = ปล่อยผ่าน" เพื่อกันคนหลุดยกระบบตอน Redis
ถูกล้าง การใช้ TTL มาบังคับหมดอายุต้องกลับกติกานั้นเป็น "ไม่มีค่า = ปฏิเสธ" ซึ่งแปลว่า
restart Redis ทีเดียวทั้งห้องเรียนหลุดพร้อมกันกลางคาบ ทางที่เลือกไม่ต้องแตะกติกานั้นเลย

## ส่วนที่ 1 — Backend

### `backend/routes.py`

- `TOKEN_LIFETIME` เปลี่ยนเป็น `timedelta(minutes=30)`
- อายุคีย์ session ใน Redis ตั้งยาวกว่า token เล็กน้อย (35 นาที) กันขอบเวลาชนกันจนคีย์
  หายไปก่อนที่ token ใบสุดท้ายจะหมดอายุ
- `generate_token(user_id, session_id=None)` รับ sid เดิมเข้ามาใช้ซ้ำได้ ถ้าไม่ส่งมาก็สุ่มใหม่
  เหมือนเดิม การล็อกอินยังสุ่ม sid ใหม่เสมอ กติกาหนึ่งบัญชีหนึ่งเครื่องจึงไม่เปลี่ยน
- เพิ่ม `POST /api/v1/auth/refresh`
  - ตรวจ token ปัจจุบันด้วย `auth_utils` ถ้าไม่ผ่านตอบ 401
  - ออก token ใบใหม่ที่ `exp` ขยับ **โดยใช้ sid เดิมจาก payload**
  - ต่ออายุคีย์ session ใน Redis
  - คืน `{'access_token': ...}`
- `POST /api/v1/auth/logout` ไม่แก้ไข พฤติกรรมเดิม (เขียน sid สุ่มทับเพื่อทำให้ token
  ใบเดิมใช้ไม่ได้) ใช้ได้กับอายุ token ใหม่อยู่แล้ว

**ทำไม refresh ต้องใช้ sid เดิม** ถ้าสุ่ม sid ใหม่ทุกครั้ง สองแท็บที่ refresh ใกล้กันจะฆ่ากันเอง
แท็บหนึ่งได้ sid ใหม่ อีกแท็บยังถือ token ที่มี sid เก่าซึ่งถูกทับไปแล้ว แล้วจะถูกเด้งออก
ทั้งที่ผู้ใช้กำลังทำงานอยู่ การใช้ sid เดิมทำให้ token เก่ากับใหม่อยู่ร่วมกันได้จนใบเก่าหมดอายุเอง

### `backend/auth_utils.py`

- แยก `payload_from_token(token)` ออกมาคืน payload ที่ถอดแล้วและตรวจ sid แล้ว
  หรือคืน `None` ถ้าไม่ผ่าน `/auth/refresh` ใช้ตัวนี้เพื่อเอา sid เดิมไปออก token ใบใหม่
- `user_id_from_token` เรียก `payload_from_token` ต่อ แล้วดึง `sub` ออกมา พฤติกรรมภายนอก
  ไม่เปลี่ยน จุดเรียกทั้ง 115 แห่งไม่ต้องแก้
- กติกา "ไม่มีค่าใน Redis = ปล่อยผ่าน" คงเดิม ไม่แตะ

## ส่วนที่ 2 — Frontend

### ไฟล์ใหม่ `src/utils/sessionToken.ts`

ที่เก็บ token ที่เดียวของทั้งแอป ไม่มีใครอ่าน `localStorage` ตรง ๆ อีก

- อ่านและเขียน `sessionStorage` แทน `localStorage` ทั้ง `token` และ object `user`
- ตอนบูตถ้า `sessionStorage` ว่าง ให้ประกาศ `REQUEST_TOKEN` ผ่าน
  `BroadcastChannel('flowquest-auth')` แล้วรอคำตอบ 200 มิลลิวินาที แท็บที่เปิดอยู่จะตอบ
  `TOKEN_SHARE` กลับมาพร้อม token และ user
- `login` และ `logout` ในแท็บใดก็ประกาศให้ทุกแท็บทำตาม

`sessionStorage` แยกกันคนละแท็บและถูกล้างเมื่อปิดแท็บ ซึ่งตอบเป้าหมายข้อ 2 และ 3
ส่วน `BroadcastChannel` ทำให้เปิดแท็บที่สองแล้วไม่ต้องล็อกอินซ้ำ

เบราว์เซอร์ที่ตั้งค่า "เปิดหน้าต่างเดิมตอนเริ่มโปรแกรม" อาจกู้ `sessionStorage` กลับมาได้
ฝั่งหน้าเว็บจึงกันไม่ได้ 100% แต่ `exp` 30 นาทีฝั่งเซิร์ฟเวอร์เป็นด่านที่กันกรณีนั้นอยู่แล้ว

### ไฟล์ใหม่ `src/utils/idleTimer.ts`

ตรรกะล้วนไม่แตะ DOM รับเวลาปัจจุบัน เวลากิจกรรมล่าสุด และเวลาที่ token ถูกออก
แล้วคืนว่าควรทำอะไร (`'ok' | 'warn' | 'logout'`) กับควร refresh หรือไม่ แยกออกมา
เพื่อเขียนเทสต์ได้โดยไม่ต้องมีเบราว์เซอร์

ค่าคงที่ ระยะ idle 30 นาที เตือนที่ 29 นาที refresh เมื่อ token อายุเกิน 15 นาที

### ไฟล์ใหม่ `src/components/SessionGuard.tsx`

แขวนไว้ใต้ `BrowserRouter` ใน `App.tsx` ทำงานเมื่อล็อกอินอยู่เท่านั้น

- ฟัง `mousemove` `keydown` `click` `scroll` `touchstart` หน่วงเหลือ 1 ครั้งต่อวินาที
  แล้วประกาศเวลากิจกรรมล่าสุดข้ามแท็บ ขยับเมาส์ที่แท็บไหนก็นับเป็นใช้งานทั้งหมด
- ถามตรรกะจาก `idleTimer.ts` ทุกวินาที
  - `'warn'` เด้งกล่องเตือนพร้อมนับถอยหลัง 60 วินาที ปุ่ม "อยู่ต่อ" นับเป็นกิจกรรม
    และสั่ง refresh ทันที
  - `'logout'` เรียก `logout()` พร้อมบันทึกเหตุผล `idle`
  - ถึงเวลา refresh ให้เรียก `POST /auth/refresh` แล้วกระจาย token ใหม่ให้ทุกแท็บ
    ถ้าสองแท็บยิงพร้อมกันก็ไม่เสียหาย เพราะ sid ไม่เปลี่ยน

### `src/store/useAuthStore.ts`

- อ่านและเขียนผ่าน `sessionToken.ts` ทั้งหมด
- เพิ่ม `authReady` เพราะการรอ `TOKEN_SHARE` 200 มิลลิวินาทีทำให้สถานะล็อกอินตอนบูต
  กลายเป็น async ถ้าไม่มีตัวนี้ `ProtectedRoute` จะเด้งไป `/login` ก่อนคำตอบมาถึง
- แก้ interceptor 401 ที่ตอนนี้เดาว่าเป็น `session_replaced` เสมอ ให้ถอด `exp` จาก token
  ที่ถืออยู่มาดูก่อน ถ้าเลยเวลาแล้วคือ `expired` ถ้ายังไม่เลยคือถูกแทนที่จริง
  ทำฝั่งหน้าเว็บเพราะฝั่งเซิร์ฟเวอร์มีจุดที่ตอบ 401 อยู่ 115 แห่ง

### `src/App.tsx`

- แสดงหน้ารอสั้น ๆ จนกว่า `authReady` เป็นจริง
- แขวน `<SessionGuard />`

### `src/pages/Login.tsx`

เพิ่มข้อความสำหรับเหตุผล `idle` และ `expired` ต่อจาก `session_replaced` ที่มีอยู่

### จุดที่ยังอ่าน `localStorage` ตรง ๆ ต้องแก้ตาม

## ส่วนที่ 3 — การทดสอบ

### `backend/test_session_timeout.py`

รูปแบบเดียวกับ `test_single_session.py` ที่มีอยู่
รันด้วย `docker compose exec -T backend python test_session_timeout.py`

1. token ที่ได้จากการล็อกอินมี `exp` ห่างจากตอนนี้ประมาณ 30 นาที ไม่ใช่ 1 วัน
2. token ที่ `exp` ผ่านไปแล้ว (ประกอบขึ้นเองย้อนหลัง) ถูกปฏิเสธด้วย 401
3. `/auth/refresh` คืน token ใหม่ที่ `exp` ขยับออกไป
4. token ใบเก่าที่ยังไม่หมดอายุยังใช้งานได้หลัง `/auth/refresh`
   ข้อนี้พิสูจน์ว่า sid ไม่ถูกสุ่มใหม่ ถ้าแดงแปลว่าเปิดสองแท็บแล้วจะเด้งกันเอง
5. `/auth/refresh` ด้วย token ที่ถูกตัดเพราะไปล็อกอินเครื่องอื่น ตอบ 401
   ต่ออายุตัวเองกลับมาไม่ได้
6. `logout` ยังทำให้ token ใบนั้นใช้ไม่ได้ทันทีเหมือนเดิม
7. `backend/test_single_session.py` เดิมต้องผ่านทั้งหมด

### `frontend/tests/idle-timer.test.mjs`

## ทางที่ตัดออก

**ยิง `navigator.sendBeacon` ไปที่ `/auth/logout` ตอนปิดแท็บ** ทำให้เซิร์ฟเวอร์ตัดรอบได้
ทันทีที่ปิดเบราว์เซอร์จริง แต่เบราว์เซอร์ไม่มีทางแยกได้ว่าเหตุการณ์ `pagehide` ที่เกิดขึ้น
คือการปิดแท็บหรือการกด F5 ผลคือรีเฟรชหน้าทีเดียวก็หลุดออกจากระบบ ซึ่งรับไม่ได้สำหรับ
นักเรียนที่กำลังทำข้อสอบอยู่ จึงตัดออก แล้วอาศัย `exp` 30 นาทีเป็นขอบเขตแทน

**เปลี่ยน Redis เป็น sliding TTL 30 นาที พร้อมกลับกติกาเป็น "ไม่มีค่า = ปฏิเสธ"**
ตรงไปตรงมากว่า แต่ต้องกลับการตัดสินใจเดิมที่จงใจใส่ไว้กันคนหลุดยกระบบ ผลคือ restart
หรือล้าง Redis ทีเดียวทั้งห้องเรียนหลุดพร้อมกันกลางคาบ

**เก็บ token ไว้ใน memory ล้วนไม่แตะ storage เลย** เข้มที่สุด แต่กด F5 ก็หลุด
ขัดกับเป้าหมายข้อ 4
