# ตั้งค่าการสอบของด่าน MCQ: สลับข้อ จับเวลา และจำนวนครั้ง

วันที่: 2026-09-03

## ปัญหา

ครูตั้งกติกาการสอบของด่าน MCQ ไม่ได้ ฟอร์มมีให้กรอกแค่เกณฑ์การผ่าน (%) ทั้งที่ความสามารถบางส่วนมีอยู่ในระบบแล้วแต่ไม่มีทางเข้าถึง

สถานะจริงของแต่ละเรื่อง:

| สิ่งที่ต้องการ | สถานะเดิม |
|---|---|
| สลับคำถาม / สลับตัวเลือก | ทำงานถูกต้องแล้วใน [mcq_routes.py:129,178](../../../backend/mcq_routes.py) สลับให้เฉพาะนักเรียน ครูเห็นเรียงเดิม — ขาดแค่ช่องให้ครูตั้งค่า |
| จับเวลา | `missions.time_limit_seconds` มีอยู่ แต่ฟอร์มโชว์เฉพาะด่าน flowchart และหน้านักเรียนแสดงนาฬิกาแบบนับขึ้นโดยไม่บอกเพดานเวลา |
| หมดเวลาแล้วส่งอัตโนมัติ | ไม่มี และของเดิมทำตรงข้าม — เกินเวลาแล้วปฏิเสธการส่งด้วย 400 นักเรียนเสียงานทั้งหมด |
| จำกัดจำนวนครั้ง | ไม่มีสำหรับ MCQ ปัจจุบันด่านที่ `failed` ถูกรีเซ็ตให้ทำใหม่ไม่จำกัด |

มีบั๊กเดิมสองข้อในตรรกะเวลาที่ต้องแก้ไปพร้อมกัน:

1. [mcq_routes.py:262](../../../backend/mcq_routes.py) คิดเวลาจาก `user_mission.created_at` ซึ่งเป็นเวลาที่แถวถูกสร้างครั้งแรกและไม่รีเซ็ตเมื่อทำใหม่ ทำให้การทำรอบที่สองหมดเวลาทันที
2. เกินเวลาแล้วคืน 400 `Time limit exceeded` แทนที่จะตรวจให้คะแนนเท่าที่ทำได้

## การตัดสินใจเชิงออกแบบ

| เรื่อง | เลือก | เหตุผล |
|---|---|---|
| เก็บ `max_attempts` ที่ไหน | คอลัมน์ใหม่ `missions.max_attempts` (`0` = ไม่จำกัด) | migration เดียว ใช้ได้กับด่านทุกประเภทในอนาคต ใช้ convention เดียวกับ `SudokuPuzzle.max_attempts` ที่มีอยู่ ตารางแยกสำหรับค่าเดียวเป็นการเพิ่มความซับซ้อนเปล่า |
| ข้อที่ทำไม่ทันคิดยังไง | นับเป็นข้อที่ตอบผิด | ตัวหารเป็นจำนวนข้อทั้งหมดเสมอ ตรงกับการสอบจริงและกับเกณฑ์การผ่าน (%) ที่มีอยู่ — `finalize_mcq` หารด้วย `total_questions` อยู่แล้ว จึงไม่ต้องแก้ |
| นับจำนวนครั้งตอนไหน | ตอนส่งคำตอบ ไม่ใช่ตอนเปิดด่าน | เปิดดูแล้วออก หรือเน็ตหลุด ไม่ควรเสียสิทธิ์ |
| ผ่านแล้วทำซ้ำได้ไหม | ไม่ได้ | ตรงกับพฤติกรรมเดิม จำนวนครั้งจึงเป็นเพดานของการแก้ตัวเมื่อสอบตก ไม่ใช่การไล่เก็บคะแนน |
| endpoint สำหรับส่งอัตโนมัติ | ไม่สร้างใหม่ ใช้ `POST /mcq/<id>/complete` เดิม | endpoint นั้นเรียก `finalize_mcq` และคืนผลครบอยู่แล้ว การหมดเวลาต่างจากการกดส่งเองแค่ข้อความที่แสดง |
| ที่ตั้งค่าในหน้าครู | ฟอร์มสร้าง/แก้ไขด่านใน `TeacherDashboard.tsx` | หน้า `TeacherMCQBuilder` คือที่เขียนข้อสอบ ส่วนนี่คือกติกาการสอบ และการตั้งค่าด่านทั้งหมดอยู่ในฟอร์มเดียวกันมาตลอด |

## ขอบเขต

**ทำ:** ครูตั้งค่าสลับคำถาม สลับตัวเลือก เวลาที่กำหนด และจำนวนครั้งที่ทำได้ ของด่าน MCQ; หมดเวลาแล้วระบบตรวจให้อัตโนมัติจากคำตอบที่ทำไปแล้ว; ครบโควตาแล้วเข้าทำใหม่ไม่ได้

**ไม่ทำ (YAGNI):** เก็บประวัติคะแนนรายครั้ง, จับเวลารายข้อ, ให้เวลาเพิ่มรายบุคคล, แตะ `max_attempts` ของซูโดกุ

## Migration

migration ใหม่ต่อจาก head `b2d5a83c1f47`:

```
missions.max_attempts INTEGER NOT NULL DEFAULT 0
```

`0` แปลว่าไม่จำกัด ด่านเดิมทุกด่านจึงคงพฤติกรรมเดิม เขียน migration ให้รันซ้ำได้ตามแบบ `a1c4f7b20e91` ที่มีอยู่

## Backend

### `backend/models.py`

เพิ่ม `max_attempts = db.Column(db.Integer, default=0)` ใน `Mission`

### `backend/mission_routes.py`

- `create_mission` รับ `max_attempts` default `0`
- `update_mission` รับ `max_attempts` แบบ `if 'max_attempts' in data`
- `GET /<mission_id>` และ `GET /course/<course_id>` คืน `max_attempts` มาด้วย
- `GET /course/<course_id>` สำหรับด่าน mcq คืน `attempt_count` และ `can_retry` เพิ่ม เพื่อให้หน้าเลือกด่านแสดง "เหลืออีก N ครั้ง" และล็อกปุ่มได้ ใช้แพตเทิร์นเดียวกับที่ด่าน sudoku ใช้อยู่ (`can_replay`)

### `backend/mcq_routes.py`

**ฟังก์ชันช่วยใหม่** สองตัว ใช้ร่วมกันทุกจุด เพื่อไม่ให้ตรรกะเวลาและโควตากระจาย:

```python
def mcq_deadline_passed(mission, user_mission) -> bool
# ไม่ได้ตั้งเวลา -> False เสมอ
# ไม่มี started_at -> False
# เกิน (time_limit_seconds + 5) วินาทีนับจาก started_at -> True
# เผื่อ 5 วินาทีสำหรับ network lag ตามที่โค้ดเดิมเผื่อไว้

def mcq_attempts_left(mission, user_mission) -> int | None
# max_attempts = 0 -> None (ไม่จำกัด)
# มิฉะนั้นคืน max(0, max_attempts - attempt_count)
```

**`finalize_mcq`** — เพิ่มการนับครั้งที่นี่จุดเดียว เพราะทั้งการกดส่งเองและการหมดเวลาผ่านฟังก์ชันนี้ทั้งคู่ นับที่อื่นจะทำให้ตัวเลขเพี้ยน

แต่ต้องนับแบบ idempotent เพราะ docstring ของฟังก์ชันนี้ระบุว่า "Safe to call multiple times" และมีทางที่ถูกเรียกซ้ำได้จริง เช่น นักเรียนกดปุ่มจบพร้อมกับที่นาฬิกาหมดพอดี จึงต้องนับเฉพาะตอนที่เปลี่ยนสถานะจาก `pending` เป็นสถานะจบเท่านั้น:

```python
was_pending = user_mission.status == 'pending'
...
user_mission.status = 'completed' if is_passed else 'failed'
if was_pending:
    user_mission.attempt_count = (user_mission.attempt_count or 0) + 1
```

เรียกซ้ำครั้งที่สองจะเห็น status เป็น `completed`/`failed` แล้ว จึงไม่นับเพิ่ม

**`get_mcq_questions`** — ลำดับการตัดสินใจเมื่อนักเรียนเปิดด่าน:

1. ถ้ามี attempt ค้างสถานะ `pending` และ `mcq_deadline_passed()` เป็นจริง ให้เรียก `finalize_mcq` ปิดจ๊อบทันที (นักเรียนปิดแท็บหนีไปแล้วกลับมาวันหลัง ต้องไม่ได้ทำต่อ)
2. ถ้าสถานะเป็น `completed` คืนสถานะล็อกตามเดิม
3. ถ้าสถานะเป็น `failed` และยังเหลือสิทธิ์ รีเซ็ตให้ทำใหม่ตามเดิม (ลบ `MCQUserAnswer`, `status='pending'`, `started_at=utcnow()`)
4. ถ้าสถานะเป็น `failed` และหมดสิทธิ์แล้ว **ไม่รีเซ็ต** คืนสถานะล็อกพร้อมคะแนนครั้งสุดท้าย

response เพิ่มฟิลด์ `time_limit_seconds`, `started_at`, `attempts_left`, `max_attempts`, `locked` (bool)

**`submit_mcq_single`** — ปฏิเสธด้วย 403 เมื่อ `mcq_deadline_passed()` เป็นจริง กันการแก้นาฬิกาเครื่องตัวเองแล้วตอบต่อหลังหมดเวลา

**`submit_mcq`** (endpoint ส่งทีเดียวทั้งชุด) — แก้บั๊กเดิม: ใช้ `started_at` แทน `created_at` และเมื่อเกินเวลาให้ตรวจให้คะแนนเท่าที่ทำได้แทนการคืน 400

**`complete_mcq`** — การหมดเวลายิงมาที่ endpoint นี้ด้วย จึงต้องไม่ปฏิเสธ attempt ที่กำลังทำอยู่:

- ถ้า `user_mission.status == 'pending'` เรียก `finalize_mcq` ตามปกติ ไม่ว่าจะเลยเวลาหรือยัง (นี่คือเส้นทางของการส่งอัตโนมัติ ต้องผ่านเสมอ)
- ถ้าสถานะจบไปแล้ว คืนผลเดิมโดยไม่นับครั้งเพิ่ม (การเรียกซ้ำไม่ควรเป็น error)

การกันไม่ให้เริ่มรอบใหม่เมื่อหมดสิทธิ์ อยู่ที่ `get_mcq_questions` ข้อ 4 ไม่ใช่ที่นี่ เพราะ `complete_mcq` เป็นทางออกของ attempt ที่เริ่มไปแล้ว ไม่ใช่ทางเข้า

เวลาเป็นของ server เสมอ คำนวณจาก `started_at` ไม่เชื่อค่าใดจาก client

## Frontend — ฝั่งครู

`frontend/src/pages/TeacherDashboard.tsx`

- `interface Mission` เพิ่ม `max_attempts?: number`, `randomize_questions?: boolean`, `randomize_choices?: boolean`
- `formData` เพิ่ม `max_attempts: 0`, `randomize_questions: false`, `randomize_choices: true` — ค่าเริ่มต้นตรงกับ default ในฐานข้อมูล เพื่อไม่ให้ด่านเดิมเปลี่ยนพฤติกรรม
- `openEditModal` ต้องอ่านค่าเดิมทั้งสามจาก mission object ที่ API ส่งมา มิฉะนั้นครูเปิดฟอร์มไปแก้แค่ชื่อด่าน แล้วบันทึก จะเผลอรีเซ็ตการสลับข้อกลับเป็นค่าเริ่มต้น
- บล็อก `formData.mission_type === 'mcq'` ในฟอร์ม เพิ่มจาก 1 ช่องเป็น 4:

| ช่อง | ชนิด | ค่าเริ่มต้น |
|---|---|---|
| เกณฑ์การผ่าน (%) | ตัวเลข 1-100 | 70 (เดิม) |
| เวลาที่กำหนด (นาที) | ตัวเลข เว้นว่าง = ไม่จับเวลา | ว่าง |
| จำนวนครั้งที่ทำได้ | ตัวเลข `0` = ไม่จำกัด | 0 |
| สลับคำถาม / สลับตัวเลือก | checkbox 2 อัน | ❌ / ✅ |

`time_limit_seconds` เก็บเป็นวินาทีแต่ครูกรอกเป็นนาที แปลงหน่วยแบบเดียวกับที่บล็อก flowchart ทำอยู่

## Frontend — ฝั่งนักเรียน

`frontend/src/components/LiveTimer.tsx`

- เพิ่ม prop `onExpire?: () => void` ยิงครั้งเดียวเมื่อ `elapsed >= timeLimitSeconds` ป้องกันการยิงซ้ำด้วย `useRef`
- ไม่แตะการแสดงผลเดิม คอมโพเนนต์รับ `timeLimitSeconds` และเปลี่ยนเป็นสีเหลือง/แดงเมื่อใกล้หมดอยู่แล้ว

`frontend/src/pages/StudentMCQPlayer.tsx`

- ส่ง `timeLimitSeconds` เข้า `LiveTimer` (ตอนนี้ไม่ได้ส่ง จึงไม่มีใครเห็นเพดานเวลา)
- ต่อ `onExpire` เข้ากับ `handleComplete` ที่มีอยู่ พร้อม state `isTimeUp` เพื่อให้หน้าผลลัพธ์พาดหัวว่า "หมดเวลา" แทนหัวข้อปกติ
- เมื่อ `isTimeUp` ปิดปุ่มตอบข้อถัดไปทั้งหมด
- แสดง "เหลืออีก N ครั้ง" เมื่อครูตั้งลิมิตไว้ ซ่อนเมื่อไม่จำกัด
- ถ้า API คืน `locked` แสดงหน้าคะแนนครั้งสุดท้ายพร้อมข้อความว่าใช้สิทธิ์ครบแล้ว

`frontend/src/pages/MissionSelect.tsx`

- ด่าน mcq ที่ `can_retry` เป็นเท็จ แสดงสถานะล็อกและกดเข้าไม่ได้ ใช้แพตเทิร์นเดียวกับด่าน sudoku ที่ใช้ `can_replay` อยู่

## Testing

เขียน `backend/test_mcq_settings.py` แยกไฟล์ ตามแบบ `backend/test_mission_visibility.py` (Flask test client, สร้าง fixture ใน DB จริงแล้วลบทิ้งเสมอในทุกทางออก) ครอบ:

1. หมดเวลาแล้ว `submit-single` ถูกปฏิเสธ 403 แต่ `/complete` ยังตรวจให้คะแนนได้
2. เปิดด่านที่ค้าง `pending` มาเกินเวลา ถูกปิดจ๊อบอัตโนมัติและไม่ได้ทำต่อ
3. ตอบถูก 3 จาก 5 ข้อแล้วหมดเวลา ได้ 60% ไม่ใช่ 100% (ข้อที่ไม่ได้ตอบนับเป็นผิด)
4. `attempt_count` เพิ่มครั้งละ 1 ต่อการส่ง 1 ครั้ง และไม่เพิ่มเมื่อแค่เปิดด่าน
5. `max_attempts=2` สอบตก 2 ครั้งแล้วเข้าไม่ได้อีก; `max_attempts=0` ทำได้ไม่จำกัด
6. สอบผ่านตั้งแต่ครั้งแรกแล้วทำซ้ำไม่ได้ แม้ยังเหลือสิทธิ์
7. เวลาคิดจาก `started_at` ที่รีเซ็ตทุกครั้งที่เริ่มรอบใหม่ ไม่ใช่ `created_at` (กันบั๊กเดิมกลับมา)
8. ครูเรียก `get_mcq_questions` ได้คำถามเรียงตามลำดับเดิมแม้เปิดสลับไว้

## เกณฑ์ว่าเสร็จ

- ครูตั้งค่าครบทั้ง 4 อย่างในฟอร์มด่าน MCQ และค่าเดิมไม่ถูกรีเซ็ตเมื่อเปิดฟอร์มไปแก้อย่างอื่น
- นักเรียนเห็นนาฬิกาพร้อมเพดานเวลา และเมื่อหมดเวลาระบบตรวจให้เองพร้อมพาดหัวว่าหมดเวลา
- ปิดแท็บหนีระหว่างจับเวลา แล้วกลับมาเปิดใหม่ ไม่ได้ทำต่อ
- ครบโควตาแล้วเข้าทำใหม่ไม่ได้ทั้งจากหน้าเลือกด่านและจากลิงก์ตรง
- สอบผ่านแล้วทำซ้ำไม่ได้
- ด่าน MCQ เดิมที่มีอยู่ยังทำงานเหมือนเดิมทุกประการ (ไม่จับเวลา ไม่จำกัดครั้ง สลับตัวเลือกแต่ไม่สลับคำถาม)
- `docker compose exec backend python test_mission_visibility.py` ยังผ่านทั้งหมด (ไม่ทำของเดิมพัง)
