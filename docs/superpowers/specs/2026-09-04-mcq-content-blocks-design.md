# แทรกรูปภาพในคำถามและตัวเลือกของด่าน MCQ

วันที่: 2026-09-04

## ปัญหา

ครูใส่รูปในข้อสอบ MCQ ได้แค่รูปเดียวต่อคำถาม และอีกรูปเดียวต่อตัวเลือก โดยตำแหน่งตายตัวคือ **อยู่เหนือข้อความเสมอ** เขียนคำถามแบบ "จากผังงานด้านล่าง [รูป] ผลลัพธ์คือข้อใด" ไม่ได้ และการอัปโหลดมีทางเดียวคือกดปุ่มเลือกไฟล์

สถานะเดิมของแต่ละส่วน:

| ส่วน | สถานะเดิม |
|---|---|
| ฐานข้อมูล | `mcq_questions.image_url` และ `mcq_choices.image_url` อย่างละคอลัมน์เดียว เก็บได้รูปเดียว ไม่มีข้อมูลตำแหน่ง |
| อัปโหลด | `POST /api/v1/upload` ใน [app.py:83](../../../backend/app.py) ใช้งานได้ดีอยู่แล้ว คืน `{"url": "/api/v1/uploads/<ชื่อไฟล์>"}` จำกัด 5MB รับ png/jpg/jpeg/gif/webp |
| หน้าครู | [TeacherMCQBuilder.tsx:293](../../../frontend/src/pages/TeacherMCQBuilder.tsx) มีปุ่ม `<input type="file">` อย่างเดียว ลากวางไม่ได้ วางจากคลิปบอร์ดไม่ได้ |
| หน้านักเรียน | [StudentMCQPlayer.tsx:630,660](../../../frontend/src/pages/StudentMCQPlayer.tsx) แสดงรูปด้วย `<img>` ตรง ๆ ขนาดจำกัด `max-h-64` กดขยายไม่ได้ |

## การตัดสินใจเชิงออกแบบ

| เรื่อง | เลือก | เหตุผล |
|---|---|---|
| รูปแบบการแก้ไข | ลิสต์บล็อก `text` / `image` เรียงต่อกัน | ได้ "รูปแทรกกลางข้อความ" ตามที่ต้องการ โดยเก็บเป็น JSON ที่มีโครงสร้างชัดเจน ไม่ต้องลง rich text editor ใหม่ ไม่ต้อง sanitize HTML และหน้านักเรียนเรนเดอร์ตรงไปตรงมา |
| เก็บที่ไหน | คอลัมน์ใหม่ `content_blocks` (JSON, nullable) ทั้งสองตาราง | เพิ่มอย่างเดียว ไม่แตะข้อมูลเดิม ข้อสอบที่มีอยู่ไม่ต้อง migrate และไม่มีจังหวะไหนที่พัง |
| `question_text` / `choice_text` เอาไงต่อ | เก็บไว้ และให้ backend คำนวณจาก text blocks ตอนบันทึก | สองที่พึ่งฟิลด์นี้อยู่ — [mission_routes.py:983](../../../backend/mission_routes.py) ทำสถิติรายข้อ และ [mission_routes.py:1059](../../../backend/mission_routes.py) ส่งข้อความคำถามเข้า Gemini ตอนสรุปผล การ derive ทำให้ทั้งสองที่ไม่ต้องแก้เลย และข้อความสองชุดไม่มีทางไม่ตรงกันเพราะมีแหล่งความจริงเดียว |
| ข้อเก่าทำยังไง | `content_blocks` เป็น NULL แล้ว fallback ไปทางเดิม | ไม่ต้องเขียนสคริปต์แปลงข้อมูล ครูเปิดแก้เมื่อไรจึงค่อยกลายเป็นบล็อก |
| ตำแหน่งที่วางรูปตอนลากวาง | ต่อท้ายลิสต์เสมอ แล้วให้ลาก ⠿ ไปแทรกเอง | ตรวจว่าเมาส์อยู่ระหว่างบล็อกไหนตอนลากไฟล์เป็นงานที่ซับซ้อนกว่ามาก และได้ผลลัพธ์เดียวกันในสองก้าว |
| endpoint อัปโหลด | ใช้ `POST /api/v1/upload` เดิม | endpoint นี้ทำครบแล้ว ทั้งตรวจสิทธิ์ ตรวจนามสกุล และตั้งชื่อไฟล์ไม่ซ้ำด้วย uuid |
| ตัวแสดงผล | คอมโพเนนต์เดียวใช้ทั้ง 3 หน้า | ตอนนี้โค้ดแสดงรูปถูกคัดลอกไว้ 2 ที่และขนาดไม่ตรงกันแล้ว การรวมเป็นตัวเดียวทำให้ครูเห็นตรงกับที่นักเรียนเห็นเสมอ |

## ขอบเขต

**ทำ:** ครูแทรกข้อความและรูปสลับกันได้อิสระในคำถามและในตัวเลือก ของชนิด `multiple_choice` และ `true_false`; อัปโหลดด้วยการลากไฟล์มาวาง; วางรูปจากคลิปบอร์ดด้วย Ctrl+V; สลับลำดับบล็อกด้วยการลาก; นักเรียนกดรูปเพื่อขยายเต็มจอ

**ไม่ทำ (YAGNI):** ชนิดคำถาม `matching` / `categorize` / `fill_blank` และช่องคำอธิบายเฉลย ยังเป็นข้อความล้วนเหมือนเดิม; ลากหลายไฟล์พร้อมกัน; ครูกำหนดขนาดรูปเอง; ลบไฟล์รูปที่ไม่ถูกใช้แล้วออกจากดิสก์ (ระบบเดิมก็ไม่ได้ลบอยู่แล้ว ถ้าต้องการค่อยแยกเป็นงานเก็บกวาดต่างหาก)

## รูปแบบของบล็อก

```json
[
  { "type": "text",  "value": "จากผังงานด้านล่าง" },
  { "type": "image", "url": "/api/v1/uploads/ab12cd_flow.png", "alt": "" },
  { "type": "text",  "value": "ผลลัพธ์ที่ได้คือข้อใด?" }
]
```

- `text.value` — string ตัดช่องว่างหัวท้าย บล็อกที่เหลือเป็นค่าว่างถูกตัดทิ้งตอนบันทึก
- `image.url` — path ที่ `POST /api/v1/upload` คืนมา
- `image.alt` — string ว่างได้ ใช้เป็น `alt` ของ `<img>`

## Migration

migration ใหม่ต่อจาก head `c3e6b94d2a58`:

```
mcq_questions.content_blocks JSON NULL
mcq_choices.content_blocks   JSON NULL
```

ทั้งสองคอลัมน์ nullable ไม่มี default แถวเดิมทุกแถวจึงเป็น NULL และคงพฤติกรรมเดิม เขียนให้รันซ้ำได้ตามแบบ `a1c4f7b20e91`

## Backend

### `backend/models.py`

เพิ่ม `content_blocks = db.Column(db.JSON, nullable=True)` ใน `MCQQuestion` และ `MCQChoice`

### `backend/mcq_routes.py`

**อ่าน** — เพิ่ม `content_blocks` ใน `question_dict` และ `choice_dict` ของทั้ง `GET /<mission_id>/questions` (บรรทัด ~215, ~224) และ endpoint ทบทวนคำตอบ (บรรทัด ~513) ส่งให้ทั้งครูและนักเรียน บล็อกไม่มีข้อมูลเฉลยจึงไม่รั่ว

**เขียน** — `PUT /<mission_id>/questions` รับ `content_blocks` ของแต่ละคำถามและแต่ละตัวเลือก แล้ว derive ข้อความ

ฟังก์ชันช่วยตัวใหม่ในไฟล์เดียวกัน:

```python
def normalize_blocks(raw):
    """คืน (blocks, plain_text) หรือ raise ValueError ถ้า payload ไม่ถูกต้อง"""
```

กติกาของ `normalize_blocks`:

1. `raw` เป็น `None` → คืน `(None, None)` แปลว่าข้อนี้ยังใช้ฟิลด์เดิม
2. ไม่ใช่ list → `ValueError`
3. ยาวเกิน 20 บล็อก → `ValueError`
4. แต่ละบล็อกต้องเป็น dict ที่ `type` เป็น `text` หรือ `image` เท่านั้น
5. `text` — `value` ต้องเป็น string ยาวไม่เกิน 5000 ตัวอักษร ตัดช่องว่างหัวท้าย ถ้าว่างให้ทิ้งบล็อกนั้น
6. `image` — `url` ต้องเป็น string ที่ **ขึ้นต้นด้วย `/api/v1/uploads/`** และไม่มี `..` มิฉะนั้น `ValueError` ข้อนี้กันการยัด URL ภายนอกหรือ `javascript:` เข้ามาทาง API ตรง ๆ ซึ่งจะกลายเป็น `<img src>` ในเบราว์เซอร์ของนักเรียนทุกคน
7. `plain_text` = เอา `value` ของ text blocks มาต่อกันด้วย `\n` ถ้าไม่มี text block เลยให้เป็น `"[รูปภาพ]"` เพื่อไม่ให้สถิติรายข้อและ prompt ของ Gemini ได้บรรทัดว่าง

ตอนบันทึกแต่ละคำถาม:

- ถ้ามี `content_blocks` → `question_text` ใช้ `plain_text` ที่ derive มา (ไม่สนค่าที่ client ส่งมา) และ `image_url` ตั้งเป็น `None` เพื่อไม่ให้รูปซ้ำสองระบบ
- ถ้าไม่มี → เก็บ `question_text` / `image_url` ตามเดิมทุกประการ

ตัวเลือกใช้กติกาเดียวกันกับ `choice_text` / `image_url`

`ValueError` ที่หลุดมาจากการ validate ให้ตอบ `400` พร้อมข้อความว่าคำถามข้อที่เท่าไรมีปัญหา และ **ไม่ commit** — endpoint นี้ลบคำถามเดิมทั้งหมดก่อนสร้างใหม่ ([mcq_routes.py:280](../../../backend/mcq_routes.py)) ถ้า validate ล้มกลางทางแล้ว commit ไป ข้อสอบจะหายทั้งชุด จึงต้อง validate **ทุกข้อให้ครบก่อน** แล้วค่อยเริ่มลบและเขียน

## Frontend

### `frontend/src/components/mcq/blocks.ts`

ชนิดข้อมูลและตัวช่วยที่ทั้งสองคอมโพเนนต์ใช้ร่วมกัน

```ts
export type ContentBlock =
  | { type: 'text'; value: string }
  | { type: 'image'; url: string; alt?: string };

// แปลงฟิลด์เดิมเป็นบล็อก ใช้ตอนเปิดข้อเก่าขึ้นมาแก้ และตอนแสดงผล
export function toBlocks(
  blocks: ContentBlock[] | null | undefined,
  legacyText: string,
  legacyImageUrl?: string,
): ContentBlock[];

// ต่อ path ของรูปกับ VITE_API_BASE_URL
export function resolveImageUrl(url: string): string;
```

`toBlocks` เมื่อไม่มี `blocks` จะคืน `[image?, text]` ตามลำดับเดิม (รูปอยู่บน) — พฤติกรรมของข้อเก่าจึงเหมือนเดิมเป๊ะ

`resolveImageUrl` รวมตรรกะ `import.meta.env.VITE_API_BASE_URL ? ... + url : url` ที่ตอนนี้เขียนซ้ำอยู่ 4 ที่

### `frontend/src/components/mcq/ContentBlockEditor.tsx`

```tsx
interface Props {
  blocks: ContentBlock[];
  onChange: (blocks: ContentBlock[]) => void;
  variant: 'question' | 'choice';
  placeholder?: string;
}
```

- ลิสต์บล็อกเรียงบนลงล่าง แต่ละบล็อกมีที่จับ ⠿ และปุ่มลบ
- บล็อก `text` — `<textarea>` ที่ยืดตามเนื้อหา
- บล็อก `image` — รูปตัวอย่าง + ช่องกรอกคำบรรยาย (`alt`) + ปุ่มลบ
- สลับลำดับด้วย `@dnd-kit/sortable` (`DndContext` + `SortableContext` + `useSortable`) ซึ่งเป็น dependency ที่โปรเจกต์มีอยู่แล้ว
- ปุ่ม `+ เพิ่มข้อความ` และ `+ เพิ่มรูป` ต่อท้ายลิสต์
- **ลากไฟล์มาวาง** — `onDragOver` / `onDragLeave` / `onDrop` ที่กรอบนอกสุด ระหว่างลากผ่านให้ขอบเป็นเส้นประสีม่วงพร้อมข้อความ "วางรูปที่นี่" วางแล้วอัปโหลดและต่อบล็อกรูปท้ายลิสต์
- **วางจากคลิปบอร์ด** — `onPaste` ที่กรอบเดียวกัน อ่าน `e.clipboardData.files` ถ้ามีไฟล์รูปให้ `preventDefault` แล้วอัปโหลด ผูกกับกรอบไม่ใช่ `window` เพื่อให้รูปไปลงข้อที่กำลังโฟกัสอยู่เท่านั้น
- ระหว่างอัปโหลดแสดงบล็อกโครงร่างพร้อมสปินเนอร์ เพื่อให้เห็นว่าระบบรับไฟล์แล้ว

ตรวจก่อนยิงอัปโหลด แล้วแจ้งด้วย Swal ภาษาไทยถ้าไม่ผ่าน:

- นามสกุลต้องเป็น png / jpg / jpeg / gif / webp — ตรงกับ `ALLOWED_EXTENSIONS` ใน [app.py:97](../../../backend/app.py)
- ขนาดต้องไม่เกิน 5MB — ตรงกับ `MAX_CONTENT_LENGTH` ใน [app.py:33](../../../backend/app.py) ถ้าปล่อยให้เกินแล้วส่งไป Flask จะตอบ 413 เป็นหน้า HTML ซึ่ง axios จะโยน error ที่ผู้ใช้อ่านไม่รู้เรื่อง ภาพจับหน้าจอความละเอียดสูงชนเพดานนี้ได้ง่าย

### `frontend/src/components/mcq/ContentBlockView.tsx`

```tsx
interface Props {
  blocks?: ContentBlock[] | null;
  text: string;              // ฟิลด์เดิม ใช้เมื่อ blocks ว่าง
  imageUrl?: string;         // ฟิลด์เดิม ใช้เมื่อ blocks ว่าง
  size: 'question' | 'choice';
}
```

- เรียก `toBlocks` แล้วเรนเดอร์ตามลำดับ ข้อความคง `whitespace-pre-wrap`
- `size="question"` — รูปกว้างเต็มคอนเทนเนอร์ `w-full` สูงไม่เกิน `max-h-[60vh]` และ `object-contain`
- `size="choice"` — รูปสูงไม่เกิน `max-h-32` พอให้เห็นว่าเป็นรูปอะไร
- คลิกรูปเปิด lightbox เต็มจอ ปิดด้วยการคลิกพื้นหลังหรือกด Esc

lightbox ต้องเป็น overlay ที่จำกัดความสูงตามแนวทางเดียวกับ modal อื่นในโปรเจกต์ คือ `fixed inset-0 ... p-4` แล้วให้รูปข้างในเป็น `max-h-full max-w-full object-contain` **ห้ามใช้หน่วย `dvh`** เพราะเบราว์เซอร์เก่าจะทิ้งทั้งบรรทัดแล้วกลับไปล้นจอเงียบ ๆ

ในหน้านักเรียน การคลิกรูปต้องไม่ไปเลือกตัวเลือกนั้นด้วย — ตัว `<img>` ในบล็อกของตัวเลือกจึงต้อง `stopPropagation`

## กรณีขอบ

| กรณี | พฤติกรรมที่ต้องการ |
|---|---|
| ข้อสอบเก่าที่ `content_blocks` เป็น NULL | แสดงเหมือนเดิม รูปอยู่เหนือข้อความ ทั้งหน้าครูและหน้านักเรียน |
| ครูเปิดข้อเก่าแล้วกดบันทึกโดยไม่แก้อะไร | กลายเป็นบล็อก `[image, text]` ผลลัพธ์ที่ตาเห็นเหมือนเดิม |
| คำถามที่มีแต่รูป ไม่มีข้อความ | บันทึกได้ `question_text` เป็น `"[รูปภาพ]"` สถิติรายข้อและ prompt ของ Gemini จึงไม่ได้บรรทัดว่าง |
| อัปโหลดล้มกลางทาง | ไม่เพิ่มบล็อก แสดง Swal บอกเหตุผล บล็อกโครงร่างหายไป |
| ไฟล์ใหญ่เกิน 5MB หรือผิดชนิด | บอกก่อนยิงเซิร์ฟเวอร์ ไม่ปล่อยให้ไปเจอ 413 |
| payload มี url ที่ไม่ได้ขึ้นต้นด้วย `/api/v1/uploads/` | 400 ไม่บันทึกอะไรเลย ข้อสอบเดิมยังอยู่ครบ |
| ครูเปิดสลับลำดับตัวเลือก | บล็อกติดไปกับตัวเลือกอยู่แล้ว ไม่ต้องแก้อะไรใน `random.shuffle` |
| ลบบล็อกรูป | ไฟล์ยังค้างใน `uploads/` ตามพฤติกรรมเดิมของระบบ |

## การตรวจสอบ

### สคริปต์ backend

`backend/test_mcq_blocks.py` ตามแบบ `test_mcq_settings.py` ที่มีอยู่ — สร้างข้อมูลชั่วคราวใน DB จริงแล้วลบทิ้งเสมอเมื่อจบ รันด้วย `docker compose exec backend python test_mcq_blocks.py`

ต้องครอบคลุม:

1. `PUT` คำถามที่มี blocks แล้ว `GET` กลับมาได้ blocks ครบและเรียงถูก
2. `question_text` ที่ derive แล้วเท่ากับ text blocks ต่อกันด้วย `\n`
3. คำถามที่มีแต่รูป ได้ `question_text` เป็น `"[รูปภาพ]"`
4. ตัวเลือกก็เก็บ blocks ได้เหมือนกัน
5. url ที่ไม่ได้ขึ้นต้นด้วย `/api/v1/uploads/` ถูกปฏิเสธด้วย 400
6. payload เสียไม่ทำให้ข้อสอบเดิมหาย — ยิง payload ผิดใส่ด่านที่มีข้อสอบอยู่แล้ว จากนั้น `GET` ต้องยังได้ข้อสอบเดิมครบ
7. `type` แปลก ๆ และบล็อกเกิน 20 ถูกปฏิเสธด้วย 400
8. แถวที่ `content_blocks` เป็น NULL ยัง `GET` ได้ปกติและคืน `image_url` เดิม

### ตรวจในแอปจริง

1. ครูสร้างคำถามที่เป็น [ข้อความ][รูป][ข้อความ] → บันทึก → รีโหลดหน้า → ลำดับต้องคงเดิม
2. ลากไฟล์รูปจาก Finder มาวางในการ์ดคำถาม → ขึ้นบล็อกรูป
3. จับภาพหน้าจอแล้ว Cmd+V ในการ์ดตัวเลือก → ขึ้นบล็อกรูปในตัวเลือกนั้น ไม่ใช่ข้ออื่น
4. ลาก ⠿ สลับลำดับ → บันทึก → ลำดับใหม่คงอยู่
5. เข้าเล่นเป็นนักเรียน → เห็นข้อความและรูปเรียงตรงกับที่ครูจัด กดรูปแล้วขยายเต็มจอ กดรูปในตัวเลือกแล้วต้องไม่เผลอเลือกข้อนั้น
6. เปิดข้อสอบเก่าที่ทำไว้ก่อนหน้า → ต้องแสดงเหมือนเดิมทั้งฝั่งครูและนักเรียน
7. หน้าสรุปผลของครู (`StudentMCQView`) แสดงตรงกับที่นักเรียนเห็น
