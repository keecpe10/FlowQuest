# เนื้อหาแบบ rich text ในคำถามและตัวเลือกของด่าน MCQ

วันที่: 2026-09-04 (ปรับรอบสอง: เปลี่ยนจากลิสต์บล็อกเป็น rich text editor)

> **บันทึกการเปลี่ยนแปลง** — ฉบับแรกออกแบบเป็น "ลิสต์บล็อกข้อความ/รูป เรียงต่อกัน"
> และทำเสร็จไปแล้ว แต่พอใช้จริงพบว่ายังไม่ตรงกับที่ต้องการสองเรื่อง คือรูปต้อง
> **ไหลอยู่ในบรรทัดเดียวกับข้อความ** และครูอยากได้ตัวแก้ไขที่**พิมพ์ต่อเนื่องได้
> พร้อมทูลบาร์** (ตัวหนา ตัวเอียง รายการหัวข้อ แทรกรูป) จึงเปลี่ยนมาใช้ TipTap
> เอกสารฉบับนี้อธิบายรูปแบบที่ใช้จริงในปัจจุบัน

## ปัญหา

ครูใส่รูปในข้อสอบ MCQ ได้แค่รูปเดียวต่อคำถาม และอีกรูปเดียวต่อตัวเลือก โดยตำแหน่งตายตัวคือ **อยู่เหนือข้อความเสมอ** เขียนคำถามแบบ "จากผังงานด้านล่าง [รูป] ผลลัพธ์คือข้อใด" ไม่ได้ และการอัปโหลดมีทางเดียวคือกดปุ่มเลือกไฟล์

สถานะเดิมของแต่ละส่วน:

| ส่วน | สถานะเดิม |
|---|---|
| ฐานข้อมูล | `mcq_questions.image_url` และ `mcq_choices.image_url` อย่างละคอลัมน์เดียว เก็บได้รูปเดียว ไม่มีข้อมูลตำแหน่ง |
| อัปโหลด | `POST /api/v1/upload` ใน [app.py:83](../../../backend/app.py) ใช้งานได้ดีอยู่แล้ว คืน `{"url": "/api/v1/uploads/<ชื่อไฟล์>"}` จำกัด 5MB รับ png/jpg/jpeg/gif/webp |
| หน้าครู | [TeacherMCQBuilder.tsx:293](../../../frontend/src/pages/TeacherMCQBuilder.tsx) มีปุ่ม `<input type="file">` อย่างเดียว ลากวางไม่ได้ วางจากคลิปบอร์ดไม่ได้ |
| หน้านักเรียน | [StudentMCQPlayer.tsx:630,660](../../../frontend/src/pages/StudentMCQPlayer.tsx) แสดงรูปด้วย `<img>` ตรง ๆ ขนาดจำกัด `max-h-64` กดขยายไม่ได้ |
| หน้าครูดูย้อนหลัง | [StudentMCQView.tsx:200,223](../../../frontend/src/pages/StudentMCQView.tsx) โค้ดแสดงผลคัดลอกซ้ำจากหน้านักเรียน ขนาดไม่ตรงกัน (`max-h-48` กับ `max-h-64`) |

## การตัดสินใจเชิงออกแบบ

| เรื่อง | เลือก | เหตุผล |
|---|---|---|
| รูปแบบการแก้ไข | rich text editor (TipTap) พิมพ์ต่อเนื่องพร้อมทูลบาร์ | ครูจัดเนื้อหาได้เหมือนพิมพ์เอกสาร และรูปเป็นโหนดแบบ inline จึงไหลไปกับข้อความในบรรทัดเดียวกันจริง ๆ ซึ่งเป็นสิ่งที่ลิสต์บล็อกทำไม่ได้ |
| เก็บเป็นอะไร | เอกสาร ProseMirror (JSON) **ไม่ใช่ HTML** | หน้าเว็บสร้าง DOM จากโครงสร้างนี้เอง ไม่มี `dangerouslySetInnerHTML` สักจุด ต่อให้มีใครเขียนอะไรแปลกปลอมลงฐานข้อมูลได้ ก็เป็นได้แค่ข้อความธรรมดา ไม่ต้องพึ่ง sanitizer ให้ถูกต้องตลอดไป |
| เก็บที่ไหน | คอลัมน์ `content_blocks` (JSON, nullable) ทั้งสองตาราง | เพิ่มอย่างเดียว ไม่แตะข้อมูลเดิม ข้อสอบที่มีอยู่ไม่ต้อง migrate และไม่มีจังหวะไหนที่พัง ชื่อคอลัมน์คงเดิมตั้งแต่ฉบับแรกเพื่อไม่ต้อง migrate ซ้ำ |
| `question_text` / `choice_text` เอาไงต่อ | เก็บไว้ และให้ backend คำนวณจาก text blocks ตอนบันทึก | สองที่พึ่งฟิลด์นี้อยู่ — [mission_routes.py:983](../../../backend/mission_routes.py) ทำสถิติรายข้อ และ [mission_routes.py:1059](../../../backend/mission_routes.py) ส่งข้อความคำถามเข้า Gemini ตอนสรุปผล การ derive ทำให้ทั้งสองที่ไม่ต้องแก้เลย และข้อความสองชุดไม่มีทางไม่ตรงกันเพราะมีแหล่งความจริงเดียว |
| ข้อเก่าทำยังไง | `content_blocks` เป็น NULL แล้ว fallback ไปทางเดิม | ไม่ต้องเขียนสคริปต์แปลงข้อมูล ครูเปิดแก้เมื่อไรจึงค่อยกลายเป็นบล็อก |
| ตำแหน่งที่วางรูป | ตรงเคอร์เซอร์ | TipTap รู้ตำแหน่งเคอร์เซอร์อยู่แล้ว จึงแทรกตรงจุดที่ครูกำลังพิมพ์ได้เลย ไม่ต้องมีขั้นตอนลากไปจัดลำดับทีหลังแบบฉบับแรก |
| endpoint อัปโหลด | ใช้ `POST /api/v1/upload` เดิม | endpoint นี้ทำครบแล้ว ทั้งตรวจสิทธิ์ ตรวจนามสกุล และตั้งชื่อไฟล์ไม่ซ้ำด้วย uuid |
| ตัวแสดงผล | คอมโพเนนต์เดียวใช้ทั้ง 3 หน้า | ตอนนี้โค้ดแสดงรูปถูกคัดลอกไว้ 2 ที่และขนาดไม่ตรงกันแล้ว การรวมเป็นตัวเดียวทำให้ครูเห็นตรงกับที่นักเรียนเห็นเสมอ |

## ขอบเขต

**ทำ:** ครูแทรกข้อความและรูปสลับกันได้อิสระในคำถามและในตัวเลือก ของชนิด `multiple_choice` และ `true_false`; อัปโหลดด้วยการลากไฟล์มาวาง; วางรูปจากคลิปบอร์ดด้วย Ctrl+V; สลับลำดับบล็อกด้วยการลาก; นักเรียนกดรูปเพื่อขยายเต็มจอ

**ไม่ทำ (YAGNI):** ชนิดคำถาม `matching` / `categorize` / `fill_blank` และช่องคำอธิบายเฉลย ยังเป็นข้อความล้วนเหมือนเดิม; ลากหลายไฟล์พร้อมกัน; ครูกำหนดขนาดรูปเอง; ลบไฟล์รูปที่ไม่ถูกใช้แล้วออกจากดิสก์ (ระบบเดิมก็ไม่ได้ลบอยู่แล้ว ถ้าต้องการค่อยแยกเป็นงานเก็บกวาดต่างหาก)

## รูปแบบของเอกสาร

เอกสาร ProseMirror มาตรฐานของ TipTap เช่นคำถาม "บล็อกคำสั่ง [รูป] จะแสดงผลอย่างไร":

```json
{"type": "doc", "content": [
  {"type": "paragraph", "content": [
    {"type": "text", "text": "บล็อกคำสั่ง "},
    {"type": "image", "attrs": {"src": "/api/v1/uploads/ab12cd_block.png", "alt": null}},
    {"type": "text", "text": " จะแสดงผลอย่างไร", "marks": [{"type": "bold"}]}
  ]}
]}
```

ชนิดที่รองรับ (ตรงกันทั้ง extension ของ TipTap ตัวตรวจฝั่ง backend และตัวเรนเดอร์):

| หมวด | ที่อนุญาต |
|---|---|
| โหนด | `doc` `paragraph` `text` `hardBreak` `image` `bulletList` `orderedList` `listItem` |
| mark | `bold` `italic` |
| attrs ของ `image` | `src` `alt` เท่านั้น — ที่เหลือถูกทิ้งตอนบันทึก |

`src` ที่เก็บลงฐานข้อมูลเป็น **path** เสมอ ไม่ใช่ URL เต็ม เพราะตอน dev หน้าเว็บกับ
backend อยู่คนละพอร์ต ถ้าเก็บ URL เต็มไว้ ข้อสอบจะพังทันทีที่ย้ายเครื่องหรือขึ้น
production ตัวแก้ไขจึงแปลง path เป็น URL เต็มตอนแสดง แล้วแปลงกลับเป็น path ตอนบันทึก

## Migration

migration ใหม่ต่อจาก head `c3e6b94d2a58`:

```
mcq_questions.content_blocks JSON NULL
mcq_choices.content_blocks   JSON NULL
```

ทั้งสองคอลัมน์ nullable ไม่มี default แถวเดิมทุกแถวจึงเป็น NULL และคงพฤติกรรมเดิม เขียนให้รันซ้ำได้ตามแบบ `a1c4f7b20e91`

## Backend

### `backend/models.py`

เพิ่ม `content_blocks = db.Column(db.JSON, nullable=True)` ใน `MCQQuestion` และ `MCQChoice`

### `backend/mcq_routes.py`

**อ่าน** — ส่ง `content_blocks` ออกใน `GET /<mission_id>/questions` (ทั้งของคำถามและตัวเลือก)
และ endpoint ทบทวนคำตอบ ส่งให้ทั้งครูและนักเรียน เอกสารไม่มีข้อมูลเฉลยจึงไม่รั่ว

**เขียน** — `normalize_content(raw, where)` คืน `(doc, plain_text)` โดย**สร้างเอกสารขึ้นใหม่
จากเฉพาะฟิลด์ที่อนุญาต** ไม่ใช่แค่ตรวจแล้วเก็บของเดิม แอตทริบิวต์แปลกปลอมอย่าง `onerror`
หรือ `srcset` จึงหายไปเองโดยไม่ต้องไล่แบล็กลิสต์

กติกา:

1. `raw` เป็น `None` → คืน `(None, None)` ใช้ฟิลด์ข้อความเดิม
2. เป็น `list` → ถือเป็นลิสต์บล็อกรูปแบบเดิม แปลงเป็นเอกสารให้อัตโนมัติ
3. เป็น dict ที่ `type` เป็น `doc` → ตรวจตามตารางชนิดข้างบน ชนิดหรือ mark นอกรายการ → `ValueError`
4. `image.src` ต้อง**ขึ้นต้นด้วย `/api/v1/uploads/`** และไม่มี `..` มิฉะนั้น `ValueError` — กันการยัด url ภายนอกหรือ `javascript:` เข้ามาทาง API ตรง ๆ
5. เพดานกันเอกสารบวม: 500 โหนด ซ้อนลึกไม่เกิน 10 ชั้น ข้อความบล็อกละไม่เกิน 5000 ตัวอักษร
6. `plain_text` = ข้อความทั้งหมดต่อกัน โดย `paragraph` / `listItem` / `hardBreak` ขึ้นบรรทัดใหม่ ถ้าไม่มีข้อความเลยแต่มีรูป → `"[รูปภาพ]"`
7. เอกสารที่ว่างทั้งข้อความและรูป (เช่นตัวเลือกที่ครูเว้นไว้) → คืน `(None, None)` เก็บเหมือนเดิมคือข้อความว่าง ไม่ใช่ปฏิเสธการบันทึกทั้งชุด

ตอนบันทึก ถ้ามีเอกสาร → `question_text` ใช้ `plain_text` ที่ derive มา (ไม่สนค่าที่ client
ส่งมา) และ `image_url` ตั้งเป็น `None` เพื่อไม่ให้รูปซ้ำสองระบบ ตัวเลือกใช้กติกาเดียวกัน

`ValueError` ตอบ `400` พร้อมบอกว่าคำถามข้อที่เท่าไรมีปัญหา และ **ไม่ commit** — endpoint นี้
ลบคำถามเดิมทั้งหมดก่อนสร้างใหม่ ([mcq_routes.py:280](../../../backend/mcq_routes.py)) ถ้า
validate ล้มกลางทางแล้ว commit ไป ข้อสอบจะหายทั้งชุด จึงต้อง validate **ทุกข้อให้ครบก่อน**
แล้วค่อยเริ่มลบและเขียน

## Frontend

ติดตั้งเพิ่ม: `@tiptap/react` `@tiptap/starter-kit` `@tiptap/extension-image`

### `frontend/src/components/mcq/blocks.ts`

ชนิดข้อมูลและตัวช่วยที่ใช้ร่วมกัน

- `RichDoc` / `RichNode` — โครงสร้างเอกสาร
- `toDoc(stored, legacyText, legacyImageUrl)` — แปลงสิ่งที่ API ส่งมาให้เป็นเอกสารเสมอ รองรับ **3 รูปแบบตามลำดับที่ระบบเคยใช้**: เอกสาร, ลิสต์บล็อก, และฟิลด์เดิม (`question_text` + `image_url` โดยรูปอยู่บน)
- `isDocEmpty(doc)` — ใช้ตรวจตอนบันทึกว่าครูกรอกคำถามหรือยัง
- `withAbsoluteImages` / `withRelativeImages` — แปลง `src` เข้า-ออกตัวแก้ไข
- `uploadImage(file, token)` — ตรวจไฟล์แล้วอัปโหลด โยน `Error` พร้อมข้อความภาษาไทย

ตรวจก่อนยิงอัปโหลดเสมอ: นามสกุลต้องตรงกับ `ALLOWED_EXTENSIONS` ใน
[app.py:97](../../../backend/app.py) และขนาดไม่เกิน 5MB ตาม `MAX_CONTENT_LENGTH` ใน
[app.py:33](../../../backend/app.py) ถ้าปล่อยให้เกิน Flask จะตอบ 413 เป็นหน้า HTML ที่ผู้ใช้
อ่านไม่รู้เรื่อง ภาพจับหน้าจอความละเอียดสูงชนเพดานนี้ได้ง่าย

### `frontend/src/components/mcq/RichContentEditor.tsx`

TipTap พร้อมทูลบาร์ **ตัวหนา / ตัวเอียง / รายการหัวข้อ / แทรกรูป** ปิด extension ที่ไม่ใช้
(heading, codeBlock, blockquote, horizontalRule, strike, code, link) เพื่อให้ชนิดที่เป็นไปได้
ตรงกับที่ backend อนุญาตพอดี

`Image.configure({ inline: true })` คือหัวใจของ "รูปแทรกกลางข้อความ" — รูปเป็นโหนดในบรรทัด
ไม่ใช่บล็อกที่ดันข้อความขึ้นบรรทัดใหม่

ใส่รูปได้ 3 ทาง: ปุ่มในทูลบาร์, ลากไฟล์มาวาง (ขอบไฮไลต์ม่วงระหว่างลากผ่าน), และ Ctrl+V

`handlePaste` ตรวจ `text/plain` ก่อนเสมอ — คลิปบอร์ดจาก Word หรือหน้าเว็บมักแนบภาพของส่วนที่
เลือกมาด้วย ถ้าไม่ตรวจ การคัดลอกข้อความมาวางจะกลายเป็นการอัปโหลดรูปแทน

### `frontend/src/components/mcq/ContentBlockView.tsx`

เรนเดอร์เอกสารเป็น React element ตรง ๆ ทีละโหนด **ไม่มี `dangerouslySetInnerHTML`**
ชนิดที่ไม่รู้จักถูกข้ามไปโดยเรนเดอร์แต่ลูกของมัน

- รูปเป็น `inline-block align-middle` จึงไหลไปกับข้อความ รูปที่กว้างเกินบรรทัดจะถูก `max-w-full` บีบแล้วตกไปอยู่บรรทัดของตัวเองตามปกติของ CSS
- คลิกรูปเปิด lightbox เต็มจอ ปิดด้วยคลิกพื้นหลังหรือ Esc
- ในหน้านักเรียนรูปอยู่ในปุ่มตัวเลือก จึงต้อง `stopPropagation` ไม่ให้การกดดูรูปกลายเป็นการตอบ

lightbox ใช้ `max-h-full` **ไม่ใช้หน่วย `dvh`** เพราะเบราว์เซอร์ที่ไม่รู้จักจะทิ้งทั้งบรรทัด
แล้วกลับไปล้นจอเงียบ ๆ

### `frontend/src/index.css`

คลาส `.mcq-rich-content` กำหนดระยะย่อหน้า จุดนำรายการ และรูปแบบ inline ของรูป
**ตัวแก้ไขของครูกับหน้าที่นักเรียนเห็นใช้คลาสเดียวกัน** สิ่งที่ครูจัดไว้จึงหน้าตาเหมือนกับ
ที่นักเรียนเห็น

ตรงกับที่โค้ดเดิมจงใจไม่ให้ใส่รูปในตัวเลือกชนิดนี้

## กรณีขอบ

| กรณี | พฤติกรรมที่ต้องการ |
|---|---|
| ข้อสอบเก่าที่ `content_blocks` เป็น NULL | แสดงเหมือนเดิม รูปอยู่เหนือข้อความ ทั้งหน้าครูและหน้านักเรียน |
| ข้อที่บันทึกเป็นลิสต์บล็อก (รูปแบบระหว่างทาง) | อ่านได้ และกลายเป็นเอกสารเมื่อบันทึกครั้งถัดไป |
| ครูเปิดข้อเก่าแล้วกดบันทึกโดยไม่แก้อะไร | กลายเป็นเอกสาร ผลลัพธ์ที่ตาเห็นเหมือนเดิม |
| คำถามที่มีแต่รูป ไม่มีข้อความ | บันทึกได้ `question_text` เป็น `"[รูปภาพ]"` สถิติรายข้อและ prompt ของ Gemini จึงไม่ได้บรรทัดว่าง |
| อัปโหลดล้มกลางทาง | ไม่แทรกรูป แสดง Swal บอกเหตุผล |
| ไฟล์ใหญ่เกิน 5MB หรือผิดชนิด | บอกก่อนยิงเซิร์ฟเวอร์ ไม่ปล่อยให้ไปเจอ 413 |
| คัดลอกข้อความจาก Word แล้ววาง | ได้ข้อความ ไม่ใช่ภาพของส่วนที่เลือก |
| payload มี `src` ที่ไม่ได้ขึ้นต้นด้วย `/api/v1/uploads/` | 400 ไม่บันทึกอะไรเลย ข้อสอบเดิมยังอยู่ครบ |
| payload มี attrs แปลกปลอม (`onerror` ฯลฯ) | ถูกทิ้งตอนบันทึก ไม่ลงฐานข้อมูล |
| ครูเปิดสลับลำดับตัวเลือก | เอกสารติดไปกับตัวเลือกอยู่แล้ว ไม่ต้องแก้อะไรใน `random.shuffle` |
| ลบรูปออกจากเนื้อหา | ไฟล์ยังค้างใน `uploads/` ตามพฤติกรรมเดิมของระบบ |

## การตรวจสอบ

### สคริปต์ backend

`backend/test_mcq_blocks.py` ตามแบบ `test_mcq_settings.py` ที่มีอยู่ — สร้างข้อมูลชั่วคราวใน
DB จริงแล้วลบทิ้งเสมอเมื่อจบ รันด้วย `docker compose exec backend python test_mcq_blocks.py`

ครอบคลุม 11 กลุ่ม: บันทึกและอ่านกลับ, รายการหัวข้อกับ mark, การ derive `question_text`,
คำถามที่มีแต่รูป, payload ที่ต้องถูกปฏิเสธ (src ภายนอก / `javascript:` / path traversal /
ชนิดโหนดและ mark แปลกปลอม / ซ้อนลึกเกิน / โหนดเกิน), การทิ้ง attrs แปลกปลอม,
payload เสียต้องไม่ทำให้ข้อสอบเดิมหาย, ลิสต์บล็อกรูปแบบเดิมยังบันทึกได้,
แถวเก่าที่เป็น NULL, สิ่งที่นักเรียนเห็นต้องไม่มีเฉลย, และตัวเลือกที่เว้นว่าง

### ตรวจในแอปจริง

1. ครูพิมพ์ "บล็อกคำสั่ง" แทรกรูป แล้วพิมพ์ "จะแสดงผลอย่างไร" → ต้องอยู่บรรทัดเดียวกัน
2. เลือกข้อความแล้วกดตัวหนา / ทำรายการหัวข้อ → บันทึก → รีโหลด → รูปแบบยังอยู่
3. ลากไฟล์รูปจาก Finder มาวาง และจับภาพหน้าจอแล้ว Ctrl+V → รูปแทรกตรงเคอร์เซอร์
4. คัดลอกข้อความจาก Word มาวาง → ได้ข้อความ ไม่ใช่รูป
5. เข้าเล่นเป็นนักเรียน → เห็นตรงกับที่ครูจัด กดรูปขยายเต็มจอได้ และกดรูปในตัวเลือกต้องไม่เผลอเลือกข้อนั้น
6. เปิดข้อสอบเก่าที่ทำไว้ก่อนหน้า → ต้องแสดงเหมือนเดิมทั้งฝั่งครูและนักเรียน
7. หน้าสรุปผลของครู (`StudentMCQView`) แสดงตรงกับที่นักเรียนเห็น
