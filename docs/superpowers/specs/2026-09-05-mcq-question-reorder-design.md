# ลากเรียงลำดับข้อสอบในแถบรายการข้อ

วันที่: 2026-09-05

ต่อจาก [การสร้างข้อสอบ MCQ ทีละข้อ](2026-09-05-mcq-builder-one-question-at-a-time-design.md) ซึ่งตัดเรื่องนี้ออกไปตาม YAGNI

## ปัญหา

แถบรายการข้อในหน้าสร้างข้อสอบเรียงตาม `order_index` แต่ครูเปลี่ยนลำดับไม่ได้ ทางเดียวที่จะสลับข้อคือลบแล้วสร้างใหม่ ซึ่งทำให้คำตอบของนักเรียนในข้อนั้นหายไปด้วย

## การตัดสินใจเชิงออกแบบ

| เรื่อง | เลือก | เหตุผล |
|---|---|---|
| จังหวะบันทึก | บันทึกทันทีตอนวาง | เข้ากับหน้านี้ที่บันทึกรายข้ออยู่แล้ว ไม่ต้องมีโหมดและปุ่มเพิ่ม |
| รูปแบบ API | `PUT .../questions/reorder` รับลิสต์ id | ตรงกับ `PUT /missions/course/<id>/reorder` ที่ระบบใช้อยู่ · ยิงครั้งเดียวและ commit รวดเดียว ลำดับจึงไม่มีทางค้างครึ่ง ๆ กลาง ๆ |
| ความเข้มของการตรวจ | ต้องส่ง id ครบทุกข้อของด่านนั้นพอดี ไม่งั้น 400 | ดูหัวข้อถัดไป |
| ที่จับลาก | ไอคอนแยกต่างหาก ไม่ลากทั้งแถว | แถวมีหน้าที่คลิกเพื่อเปิดแก้อยู่แล้ว การแยกที่จับทำให้คลิกกับลากไม่ปนกัน โดยเฉพาะบนจอสัมผัส |
| การอัปเดตหน้าจอ | สลับใน state ทันทีแล้วค่อยยิง API | ลากแล้วเห็นผลทันที ถ้าล้มเหลวค่อยคืนลำดับเดิม |
| ลากขณะมีงานค้าง | ทำได้ ไม่ต้องเตือน | `selected` ผูกกับ `question_id` ไม่ใช่ตำแหน่ง ข้อที่เปิดค้างอยู่ยังเปิดอยู่ เปลี่ยนแค่เลขข้อที่แสดง |

### ทำไมต้องส่ง id ให้ครบ

`reorder_missions` ที่มีอยู่วนลิสต์แล้วเซ็ตเฉพาะตัวที่หาเจอ ([mission_routes.py:150](../../../backend/mission_routes.py)) ถ้า client ส่งมาไม่ครบ ข้อที่ไม่ได้ส่งจะคง `order_index` เดิมไว้ แล้วเกิดค่าซ้ำกับข้อที่เพิ่งเซ็ต ผลคือลำดับที่นักเรียนเห็นขึ้นกับว่า DB คืนแถวไหนก่อน ซึ่งไม่แน่นอน

endpoint ใหม่จึงตรวจก่อนเขียนว่า `question_ids` เป็นเซ็ตเดียวกับข้อทั้งหมดของด่านนั้นพอดี — ไม่ขาด ไม่เกิน ไม่ซ้ำ ถ้าไม่ตรงให้ตอบ 400 โดยไม่แตะฐานข้อมูลเลย

## ขอบเขต

**ทำ:** ครูลากสลับลำดับข้อในแถบรายการ บันทึกทันที · ลากด้วยคีย์บอร์ดได้ · ข้อร่างลากได้เหมือนข้อปกติ

**ไม่ทำ (YAGNI):** ปุ่มเลื่อนขึ้น/ลง (คีย์บอร์ดผ่าน `KeyboardSensor` ครอบคลุมการเข้าถึงแล้ว) · ยกเลิกการเรียงย้อนกลับ · ลากข้ามด่าน

## Backend

```
PUT /api/v1/mcq/<mission_id>/questions/reorder
body: {"question_ids": [12, 9, 15]}
```

ตรวจสิทธิ์ด้วย `_teacher_mission(mission_id)` ที่มีอยู่แล้ว (ล็อกอิน → ด่านมีอยู่และเป็น `mcq` → เป็นครูของคอร์ส)

ลำดับการทำงาน:

1. `question_ids` ต้องเป็น list ไม่งั้น 400
2. ดึง `question_id` ทั้งหมดของด่านนี้ (รวมข้อร่าง) มาเทียบ ถ้า `sorted(question_ids) != sorted(ทั้งหมด)` ให้ 400 พร้อมข้อความบอกว่าต้องส่งครบทุกข้อ — เงื่อนไขนี้ดักทั้งกรณีส่งไม่ครบ ส่งเกิน ส่งซ้ำ และส่ง id ของด่านอื่น
3. เซ็ต `order_index = ตำแหน่งในลิสต์` ให้ทุกข้อ แล้ว `db.session.commit()` ครั้งเดียว
4. `socketio.emit('missions_updated')` เหมือน endpoint อื่นในไฟล์
5. ตอบ 200 `{'message': 'Questions reordered successfully'}`

## Frontend

### `QuestionList`

ห่อรายการด้วย `DndContext` + `SortableContext` (`verticalListSortingStrategy`) ตามแบบ [TeacherDashboard.tsx:1085](../../../frontend/src/pages/TeacherDashboard.tsx)

sensors ชุดเดียวกับของเดิม:

```ts
useSensors(
  useSensor(PointerSensor, { activationConstraint: { distance: 8 } }),
  useSensor(KeyboardSensor, { coordinateGetter: sortableKeyboardCoordinates }),
)
```

แต่ละแถวเปลี่ยนโครงจาก `<button>` เดี่ยว เป็น `<div ref={setNodeRef}>` ที่มี

- **ที่จับลาก** — `<button>` เล็ก ๆ ใส่ไอคอน `GripVertical` ผูก `{...attributes} {...listeners}` ไว้ตัวนี้ตัวเดียว มี `aria-label="ลากเพื่อเรียงลำดับ"`
- **ปุ่มเลือกข้อ** — เนื้อหาแถวเดิมทั้งหมด (เลขข้อ โจทย์ย่อ ชนิดข้อ ⚠️) ยัง `onClick={onSelect}` เหมือนเดิม

ขณะลากให้แถวยกขึ้นด้วย `zIndex` และเงา ตามแบบ `SortableMissionCard`

พรอปเพิ่มหนึ่งตัว: `onReorder: (questionIds: number[]) => void`

แถวชั่วคราว "ข้อใหม่ (ยังไม่บันทึก)" อยู่นอก `SortableContext` — มันยังไม่มี `question_id` จึงลากไม่ได้และไม่ควรนับเป็นรายการที่เรียงได้

### หน้าหลัก

```ts
const reorderQuestions = async (questionIds: number[]) => { ... }
```

1. เก็บลำดับเดิมไว้ แล้ว `setQuestions` เป็นลำดับใหม่ทันที
2. `PUT .../questions/reorder` พร้อม `question_ids`
3. ล้มเหลว → คืนลำดับเดิม + `Swal.fire({icon:'error', text:'เรียงลำดับไม่สำเร็จ'})`

ไม่แตะ `draft`, `dirty` หรือ `selected` เลย

## กรณีขอบ

| กรณี | พฤติกรรม |
|---|---|
| ลากทั้งที่มีงานค้าง | เรียงได้ตามปกติ ข้อที่เปิดค้างยังเปิดอยู่ เพราะ `selected` เป็น `question_id` |
| ลากขณะอยู่ในโหมดข้อใหม่ | ข้อที่บันทึกแล้วเรียงได้ แถว "ข้อใหม่" ยังอยู่ท้ายสุดและลากไม่ได้ |
| วางที่เดิม | `active.id === over.id` → ไม่ยิง API |
| มีข้อเดียว | ลากแล้วไม่มีอะไรเปลี่ยน ไม่ยิง API |
| ครูอีกคนลบข้อระหว่างที่เรากำลังลาก | ลิสต์ที่ส่งไปไม่ตรงกับของจริง → 400 → คืนลำดับเดิมและแจ้งครู ดีกว่าเขียนลำดับที่ผิดลงไป |
| ลากข้อร่าง | ได้ตามปกติ `is_draft` ไม่เกี่ยวกับลำดับ |
| นักเรียนกำลังทำค้างอยู่ | ยังเห็นลำดับที่โหลดไปแล้ว ลำดับใหม่มีผลรอบถัดไป — เหมือนการเรียงด่านที่ระบบทำอยู่แล้ว |

## การตรวจสอบ

เพิ่มใน `backend/test_mcq_single_question.py` ตามแบบเดิมของไฟล์:

| # | สิ่งที่ตรวจ |
|---|---|
| 1 | เรียงใหม่แล้ว `order_index` ตรงตามลิสต์ที่ส่ง |
| 2 | นักเรียนเรียก `GET .../questions` เห็นข้อเรียงตามลำดับใหม่ |
| 3 | ส่ง id ไม่ครบ → 400 และ `order_index` เดิมไม่ถูกแตะ |
| 4 | ส่ง id ซ้ำ → 400 |
| 5 | ส่ง id ของด่านอื่น → 400 |
| 6 | `question_ids` ไม่ใช่ list → 400 |
| 7 | ข้อร่างถูกนับรวมในลิสต์ที่ต้องส่ง และเรียงได้ |
| 8 | นักเรียนเรียก endpoint นี้ → 403 |

ฝั่งหน้าเว็บตรวจด้วยการใช้จริงผ่านเบราว์เซอร์: ลากสลับแล้วเลขข้อเรียงใหม่ถูก · โหลดหน้าซ้ำแล้วลำดับยังอยู่ · คลิกแถวยังเปิดข้อได้ไม่กลายเป็นการลาก · ลากขณะมีงานค้างแล้วข้อที่เปิดอยู่ยังเปิดอยู่
