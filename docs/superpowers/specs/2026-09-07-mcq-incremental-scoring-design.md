# ให้คะแนน MCQ ทีละข้อทันทีที่ตอบ

วันที่: 2026-09-07

ต่อจาก [ข้อสอบ MCQ แบบซูโดกุและผังงาน](2026-09-05-mcq-sudoku-flowchart-question-types-design.md) ซึ่งทำให้คะแนนรายข้อมีความหมายจริง (คะแนนบางส่วน)

## ปัญหา

คะแนนของด่าน MCQ ลงบัญชี (`PointHistory`) ตอนกดจบทั้งชุดเท่านั้น และลงเฉพาะเมื่อผ่านเกณฑ์ ระหว่างที่ทั้งห้องกำลังทำข้อสอบอยู่ อันดับผู้นำจึงเป็น 0 ทุกคนจนกว่าจะมีคนแรกทำเสร็จ นักเรียนไม่เห็นความคืบหน้าของตัวเองหรือของเพื่อนเลย ทั้งที่ระบบตรวจคำตอบทีละข้อและรู้คะแนนรายข้ออยู่แล้ว

`MCQUserAnswer.xp_awarded` เก็บคะแนนรายข้อไว้ตั้งแต่ตอนตอบ ข้อมูลมีครบแล้ว ขาดแค่การนำไปลงบัญชีที่อันดับผู้นำอ่าน

## การตัดสินใจเชิงออกแบบ

| เรื่อง | เลือก | เหตุผล |
|---|---|---|
| จังหวะให้คะแนน | ทุกครั้งที่ตอบหนึ่งข้อ | `submit_mcq_single` ตรวจและรู้คะแนนอยู่แล้ว เป็นจุดที่ข้อมูลพร้อมที่สุด |
| ถ้าไม่ผ่านเกณฑ์ | เก็บคะแนนไว้ ตอบถูกกี่ข้อได้เท่านั้น | ตรงกับสิ่งที่เห็นบนจอระหว่างทำ ถ้ายึดคืนตอนจบ นักเรียนจะเห็นคะแนนตัวเองลดลง |
| ทำซ้ำ | ใช้คะแนนรอบล่าสุด | ตอนทำใหม่ระบบลบคำตอบเก่าอยู่แล้ว ยอดจึงสะท้อนรอบปัจจุบันเอง |
| รูปแบบบัญชีคะแนน | แถวเดียวต่อ (นักเรียน, ด่าน) แล้วเขียนทับยอด | ดูหัวข้อถัดไป |
| อันดับผู้นำ | ไม่แก้ | มันรวม `PointHistory` อยู่แล้ว ย้ายจุดเขียนก็พอ |
| เรียลไทม์ | ใช้ `points_awarded` ที่มีอยู่ | `MCQLeaderboard` ฟัง event นี้อยู่แล้ว แค่ย้ายจุด emit |

## บัญชีคะแนนเปลี่ยนจาก "สร้างครั้งเดียว" เป็น "เขียนทับยอด"

ตอนนี้ `finalize_mcq` กันการให้คะแนนซ้ำด้วยการเช็คว่ามีแถวอยู่แล้วหรือยัง แล้วไม่แตะอีกเลย

```python
existing_history = PointHistory.query.filter_by(
    user_id=user_id, source='mcq_mission', source_id=mission_id).first()
if not existing_history and total_xp > 0:
    ...สร้างแถวใหม่...
```

รูปแบบนี้ใช้กับการให้คะแนนทีละข้อไม่ได้ เพราะยอดต้องขยับได้เรื่อย ๆ

เปลี่ยนเป็น **upsert**: หาแถวของ (นักเรียน, ด่าน) ถ้ามีให้เขียนทับ `points` ด้วยยอดล่าสุด ถ้าไม่มีให้สร้าง

กรณีขอบสองอย่างที่ต้องชัด:

- **ยอดเป็น 0 และยังไม่มีแถว** — ไม่ต้องสร้าง แถวคะแนน 0 ไม่มีความหมายและทำให้ตารางรก
- **ยอดเป็น 0 แต่มีแถวอยู่แล้ว** — ต้องเขียนทับเป็น 0 ห้ามข้าม เพราะเป็นกรณีที่นักเรียนทำรอบใหม่แล้วได้แย่ลง ถ้าข้ามไป คะแนนรอบเก่าจะค้างอยู่ ซึ่งขัดกับ "ใช้คะแนนรอบล่าสุด"

```
running_total = Σ xp_awarded ของคำตอบใน attempt นี้ เฉพาะข้อที่ไม่ใช่ร่าง
```

การเขียนทับแทนการบวกเพิ่มเป็นหัวใจของการกันคะแนนซ้ำ ถ้าใช้การบวก การเรียกซ้ำ (นักเรียนกดส่งรัว ๆ หรือ endpoint ถูกเรียกสองครั้ง) จะทำให้คะแนนพอง ส่วนการเขียนทับนั้น idempotent โดยธรรมชาติ — เรียกกี่ครั้งผลก็เท่ากัน

"คะแนนรอบล่าสุด" ได้มาฟรีจากคุณสมบัตินี้ เพราะ `ensure_mcq_attempt` ลบ `MCQUserAnswer` ของ attempt เดิมทิ้งเมื่อนักเรียนเริ่มทำใหม่ ยอดที่คิดใหม่จึงมาจากคำตอบรอบปัจจุบันเท่านั้น และถ้ารอบใหม่ได้น้อยกว่า ยอดในบัญชีจะลดลงตาม

## จุดที่แก้

| ไฟล์ | สิ่งที่ทำ |
|---|---|
| `backend/mcq_routes.py` | เพิ่ม `sync_mcq_points(user_id, mission, user_mission, award_xp=True)` ที่คิดยอดและ upsert · เรียกจาก `submit_mcq_single` หลังบันทึกคำตอบ · เอาบล็อกให้ XP ออกจาก `finalize_mcq` แล้วให้เรียกตัวเดียวกัน · ให้ `manual_grade` เรียกตัวเดียวกัน |

`sync_mcq_points` เป็นที่เดียวของทั้งระบบที่เขียน `PointHistory` ของด่าน MCQ ไม่ควรมีที่อื่นเขียนเองอีก ด้วยเหตุผลเดียวกับที่ `grade_answer` ถูกรวมไว้ที่เดียว

### `finalize_mcq` เหลือหน้าที่อะไร

ยังตัดสินผ่าน/ไม่ผ่าน นับครั้งสอบ ปิดสถานะ และบันทึกเวลาที่ใช้ตามเดิม แต่ไม่เป็นประตูของ XP อีกต่อไป — เรียก `sync_mcq_points` เหมือนเส้นทางอื่น เผื่อกรณีที่คะแนนยังไม่ตรง (เช่นครูกดจบให้ หรือหมดเวลาแล้วระบบส่งอัตโนมัติ)

`user_mission.score_awarded` ต้องเท่ากับยอดในบัญชีเสมอ รวมถึงตอนไม่ผ่าน เดิมโค้ดตั้งเป็น 0 เมื่อไม่ผ่าน ซึ่งขัดกับการตัดสินใจข้อ "เก็บคะแนนไว้"

### ครูทดลองทำเอง

`award_xp=False` ต้องยังทำงานเหมือนเดิม: ครูเห็นตัวเลขที่ตัวเองน่าจะได้ แต่ไม่มีแถวลงบัญชีจริงและไม่ emit `points_awarded` ออกไปกวนอันดับผู้นำของห้อง

### `manual_grade`

ตอนนี้เขียน `PointHistory` เองด้วยการลบแล้วสร้างใหม่ทุกครั้ง ให้เปลี่ยนมาเรียก `sync_mcq_points` แทน พฤติกรรมที่ได้เหมือนเดิม (ครูแก้คำตอบแล้วคะแนนขยับตาม) แต่ตรรกะอยู่ที่เดียว

## เรียลไทม์

`MCQLeaderboard` ต่อ socket ฟัง `points_awarded` อยู่แล้ว และดึงซ้ำทุก 30 วินาทีเป็นตัวสำรอง เมื่อ `sync_mcq_points` emit ทุกครั้งที่ยอดเปลี่ยน คะแนนจะขึ้นทั้งห้องทันทีที่ใครตอบถูกหนึ่งข้อ

emit เฉพาะเมื่อยอดใหม่ **ต่างจากยอดที่อยู่ในแถวก่อนหน้า** ไม่ใช่ทุกครั้งที่เรียก เพื่อไม่ให้ห้องที่มีนักเรียน 35 คนยิง event ถี่เกินจำเป็น — ตอบผิดได้ 0 คะแนน ยอดไม่ขยับ จึงไม่ต้อง emit

## ขอบเขต

**ทำ:** คะแนน MCQ ลงบัญชีทีละข้อ · เก็บคะแนนไว้แม้ไม่ผ่าน · คะแนนรอบล่าสุดเมื่อทำซ้ำ · รวมการเขียนบัญชีคะแนนไว้ที่เดียว

**ไม่ทำ (YAGNI):** ให้คะแนนระหว่างทางกับด่านซูโดกุ/ผังงาน/ระดมความคิด (คนละกลไก) · อนิเมชันคะแนนวิ่งขึ้น · แจ้งเตือนเมื่อถูกแซง · แก้อันดับผู้นำหรือ endpoint ของมัน

## ผลกระทบที่ต้องแจ้งครู

`passing_percentage` จะไม่มีผลกับคะแนนอีกต่อไป เหลือเป็นป้ายสถานะผ่าน/ไม่ผ่านที่นักเรียนและครูเห็น เดิมนักเรียนที่ทำไม่ผ่านได้ 0 คะแนน หลังเปลี่ยนจะได้คะแนนตามจำนวนข้อที่ตอบถูก

## ความเสี่ยง

| ความเสี่ยง | การรับมือ |
|---|---|
| ให้คะแนนซ้ำจากการเรียกซ้ำ | upsert เขียนทับยอด ไม่บวกเพิ่ม จึง idempotent |
| ห้องใหญ่ยิง socket ถี่ | emit เฉพาะตอนยอดเปลี่ยนจริง |
| คะแนนในบัญชีไม่ตรงกับ `score_awarded` | ทั้งคู่มาจาก `sync_mcq_points` ที่เดียว เขียนพร้อมกัน |
| ครูทดลองทำแล้วคะแนนไปโผล่ในห้อง | `award_xp=False` ไม่เขียนและไม่ emit |
