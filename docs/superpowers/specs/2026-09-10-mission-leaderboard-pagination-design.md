# แบ่งหน้าตารางอันดับตอนนักเรียนทำด่าน

วันที่ 10 กันยายน 2569

## ปัญหา

ตอนนักเรียนกำลังทำด่าน มีตารางอันดับแสดงอยู่ข้างจอสองจุด และทั้งสองจุดยังเป็น
รายการยาวที่เลื่อนดูอย่างเดียว ไม่มีการแบ่งหน้า ต่างจากหอเกียรติยศ 3D ที่เพิ่งทำ
การแบ่งหน้าไปแล้ว

| จุด | ไฟล์ | สภาพก่อนแก้ |
|---|---|---|
| ด่านผังงาน `/mission/:id` | `frontend/src/Leaderboard.tsx` | ไม่แบ่งหน้า ไม่ไฮไลต์แถวของตัวเอง ดึงซ้ำทุก 10 วินาที ไม่ใช้ socket |
| แถบข้างตอนทำข้อสอบ `/mcq/:id` | `frontend/src/components/mcq/MCQLeaderboard.tsx` | ไม่แบ่งหน้า ไฮไลต์แถวของตัวเองแล้ว ใช้ socket + สำรอง 30 วินาที |
| ซูโดกุ `/sudoku/:id` | — | ไม่มีตารางอันดับในหน้า มีแค่ปุ่มลิงก์ออกไป ไม่อยู่ในขอบเขตงานนี้ |

ทั้งสองจุดเรียก `GET /api/v1/game/leaderboard` ซึ่งคืนทุกแถวมาทีเดียว

ปัญหาที่สองซึ่งพ่วงมาด้วย: `users.avatar_url` เก็บรูปเป็น base64 ในคอลัมน์ Text
วัดจากฐานข้อมูล dev ได้เฉลี่ย 34,305 ไบต์ต่อคน สูงสุด 68,191 ไบต์ หน้าเล่นด่าน
ผังงานขอ `with_avatars=1` แล้วดึงซ้ำทุก 10 วินาที ห้องที่มีนักเรียน 40 คนทำด่าน
เดียวกันจึงเท่ากับดาวน์โหลดราว 1.3 MB ทุก 10 วินาที ต่อนักเรียนหนึ่งคน

ปัญหาที่สาม: เรียก endpoint นี้โดยไม่ระบุ `course_id` และ `mission_id` จะได้อันดับ
ทั้งโรงเรียน โดยไม่ต้องล็อกอิน เป็นช่องเดียวกับที่ปิดไปแล้วใน `/leaderboard-3d`

## ขอบเขต

ทำทั้งสองจุด (ด่านผังงาน + แถบข้างตอนทำข้อสอบ) ไม่เพิ่มตารางอันดับในหน้าซูโดกุ

## การตัดสินใจที่ตกลงกันไว้

1. **หน้าตา** เหมือนหอเกียรติยศ 3D — ตรึงอันดับ 1-3 ไว้ข้างบนเสมอ อันดับ 4 เป็นต้นไป
   แบ่งหน้าละ 10 คน มีปุ่มก่อนหน้า/ถัดไป และปุ่ม "ไปที่อันดับของฉัน"
2. **แบ่งหน้าที่ backend** ไม่ใช่ตัดหน้าที่ฝั่ง frontend เพราะการตัดที่ฝั่ง frontend
   ไม่ได้แก้เรื่อง payload รูปตัวละครซึ่งเป็นเหตุผลครึ่งหนึ่งของงานนี้
3. **แก้ความถี่ดึงข้อมูลของหน้าผังงานด้วย** ย้ายจากดึงทุก 10 วินาที ไปเป็น
   socket + สำรองทุก 30 วินาที เหมือนแถบ MCQ
4. **คงการกรองเฉพาะคนที่ลงมือทำด่านแล้ว** ตารางข้างจอตอนทำด่านมีเฉพาะคนที่กำลัง
   แข่งด้วยจริง ไม่รวมทุกคนที่ลงทะเบียนในรายวิชา จุดนี้ต่างจาก `/leaderboard-3d`
   โดยตั้งใจ เพราะหอเกียรติยศเป็นภาพรวมของรายวิชา ส่วนตารางข้างจอเป็นภาพของ
   การแข่งขันที่กำลังเกิดขึ้น
5. **เลิกฟัง `missions_updated`** (ผู้ใช้ตัดสิน 11 กันยายน 2569) หน้ากระดานระดมความคิด
   ยิง event นี้กระจายให้ทุกคนทุกครั้งที่มีคนเพิ่มหรือลบการ์ด ซึ่งไม่เคยเปลี่ยนคะแนนใคร
   ตารางอันดับจึงฟังแค่ `points_awarded` กับดึงสำรองทุก 30 วินาที
6. **ด่านผังงานต้องแจ้ง `points_awarded` ตอนส่งงานสำเร็จ** เดิม `submit_flowchart` ไม่เคย
   แจ้ง ตารางข้างจอด่านผังงานจึงขยับแค่ตามรอบสำรอง 30 วินาที ช้ากว่าการดึงทุก 10 วินาที
   ที่งานนี้มาแทน พบจากการรีวิวงานที่ 3

## สถาปัตยกรรม

### Backend — `backend/gamification.py`

`GET /api/v1/game/leaderboard` เปลี่ยนจากคืน array เป็นคืน object รูปทรงเดียวกับ
`/leaderboard-3d` ใช้ค่าคงที่ตัวเดียวกันคือ `PODIUM_SIZE = 3` และ
`LEADERBOARD_PAGE_SIZE = 10`

```json
{
  "top3":  [ { "user_id": 7, "name": "...", "avatar_url": "data:image/png;base64,...",
               "points": 120, "total_time": 340, "rank": 1 } ],
  "rows":  [ { "user_id": 42, "name": "...", "avatar_url": null,
               "points": 30, "total_time": 900, "rank": 4 } ],
  "page": 1,
  "page_size": 10,
  "total": 25,
  "total_pages": 3,
  "my_rank": 16,
  "my_page": 2,
  "my_user_id": 42
}
```

รับพารามิเตอร์ `course_id`, `mission_id`, `page`

พฤติกรรมที่เปลี่ยน

- **บังคับให้ระบุขอบเขต** ถ้าไม่มีทั้ง `course_id` และ `mission_id` ตอบ 400 พร้อม
  ข้อความ `ต้องระบุ course_id หรือ mission_id` และลบสาขา `else` ที่จัดอันดับ
  ทั้งโรงเรียนทิ้ง
- **คิวรีจัดอันดับดึงแค่ `user_id` กับตัวเลข** ไม่ select `avatar_url`, `first_name`,
  `last_name`, `username` มาทั้งตารางอีก แล้วค่อยใช้คิวรีที่สองดึงข้อมูลเต็มเฉพาะ
  แถวที่จะส่งออกจริง ซึ่งมีไม่เกิน `PODIUM_SIZE + LEADERBOARD_PAGE_SIZE` = 13 แถว
- **รูปตัวละครส่งเฉพาะสามอันดับแรก** แถวใน `rows` คืน `avatar_url` เป็น `null` เสมอ
- **ลบพารามิเตอร์ `with_avatars`** ทิ้ง เพราะไม่มีความหมายอีกต่อไป
- **หน้าที่ขอเกินช่วงให้บีบกลับ** `page` ถูกบีบเข้าช่วง 1 ถึง `total_pages` ไม่ตอบ error
  และไม่คืนรายชื่อว่าง
- **`my_rank` / `my_page`** คำนวณจาก token ของผู้เรียก ถ้าไม่มีผู้เรียกหรือผู้เรียก
  ไม่ติดอันดับให้เป็น `null` ทั้งคู่ พร้อมกับ `my_user_id` คนที่อยู่บนโพเดียมให้
  `my_page` เป็น 1 เพราะเห็นตัวเองได้จากหน้าแรกอยู่แล้ว
- **`my_user_id`** ไว้ให้หน้าเว็บเทียบว่าแถวไหนคือตัวเอง ด้วย id ไม่ใช่อันดับ

`submit_flowchart` แจ้ง `points_awarded` หลัง commit การทำด่านสำเร็จครั้งใหม่ ด้วยคีย์
`user_id`, `mission_id`, `points` แบบเดียวกับด่าน MCQ ไม่แจ้งเมื่อด่านนั้นเคยทำสำเร็จไปแล้ว
หรือเมื่อผังงานไม่ถูกต้อง

ส่วนที่คงเดิม: การกรองเหลือเฉพาะคนที่มีแถวใน `user_missions` ของด่านนั้น
(ใช้ subquery ไม่ใช่ join เพื่อไม่ให้แถวซ้ำแล้ว `sum(points)` บวมตาม),
การจัดอันดับด้วยคะแนนมากก่อนแล้วเวลาน้อยก่อน, การนับคะแนนจาก `XP_SOURCES`

### Frontend — hook ร่วมหนึ่งตัว

สร้าง `frontend/src/hooks/useMissionLeaderboard.ts` เป็นเจ้าของตรรกะทั้งหมด
ที่สองหน้าใช้ร่วมกัน

```ts
const {
  top3, rows, page, totalPages, total,
  myRank, myPage, myUserId,
  hasMission, loading, switching, justUpdated, loadFailed,
  goToPage, goToMyRank,
} = useMissionLeaderboard(missionId);
```

หน้าที่ของ hook

- ยิง `GET /api/v1/game/leaderboard?mission_id=<id>&page=<n>` พร้อม token สดที่
  อ่านด้วย `getToken()` ตอนเรียก ไม่ใช่ค่าที่ปิดทับไว้ตอนสร้าง callback
- **request-id guard** เก็บเลขลำดับที่เพิ่มขึ้นเรื่อย ๆ ให้เฉพาะคำตอบของ request
  ล่าสุดเท่านั้นที่เขียน state กันกรณีคำตอบวิ่งชนกันแล้วเด้งผู้ใช้กลับหน้า 1
- **`pageRef`** ให้ callback ของ socket อ่านหน้าปัจจุบันได้โดยไม่ต้องผูกเป็น
  dependency ของ effect ซึ่งจะทำให้ต่อ socket ใหม่ทุกครั้งที่เปลี่ยนหน้า
- ต่อ socket ฟังเฉพาะ `points_awarded` พร้อมตั้ง interval สำรองทุก 30 วินาที
  ไม่ฟัง `missions_updated` (ดูการตัดสินใจข้อ 5)
- **หน้าที่ขอกับหน้าที่แสดงแยกกัน** state `page` คือหน้าที่ขอไว้ล่าสุด ใช้สั่งดึงข้อมูล
  ส่วนค่า `page` ที่ hook คืนออกไปคือหน้าของแถวที่แสดงอยู่จริง เฉพาะคำตอบที่ไม่ใช่
  การรีเฟรชเงียบเท่านั้นที่ปรับหน้าที่ขอตามเลขหน้าที่เซิร์ฟเวอร์บีบกลับมา และถ้าการเปลี่ยน
  หน้าล้มเหลว หน้าที่ขอจะถูกคืนกลับเป็นหน้าที่แสดงอยู่ ป้ายช่วงอันดับจึงไม่มีวันขัดกับแถว
- `switching` ถูกเคลียร์ทุกครั้งที่คำขอล่าสุดจบ ไม่ว่าจะเงียบหรือไม่ กันปุ่มเปลี่ยนหน้าค้าง
  เมื่อการรีเฟรชเงียบแทรกเข้ามาแทนคำขอที่ผู้ใช้กด
- **การรีเฟรชเงียบ** การดึงซ้ำจาก socket หรือ interval ต้องไม่ทำให้รายการจางหรือ
  ขึ้นสถานะกำลังโหลด มีเฉพาะการเปลี่ยนหน้าและการโหลดครั้งแรกเท่านั้นที่แสดงสถานะ
- `justUpdated` เป็นสัญญาณกะพริบสั้น ๆ ตอนมีคนทำเสร็จ (ของเดิมในแถบ MCQ)

แยกฟังก์ชันบริสุทธิ์สำหรับข้อความบอกช่วงอันดับออกเป็นโมดูลธรรมดา
`frontend/src/utils/leaderboardRange.ts` เพื่อให้เทสต์ด้วย `node --test` ได้
โดยไม่ต้องเรนเดอร์ React

```ts
rankRangeLabel({ page, pageSize, podiumSize, total }): string
// หน้า 1 จาก 25 คน -> "อันดับ 4–13 จาก 25"
// หน้า 3 จาก 25 คน -> "อันดับ 24–25 จาก 25"
// ไม่มีใครนอกโพเดียม   -> ""
```

### Frontend — สอง component

ทั้งสองไฟล์เหลือหน้าที่แสดงผลอย่างเดียว หน้าตา สี และทรงเดิมไม่เปลี่ยน

`frontend/src/Leaderboard.tsx` (การ์ดขาวในหน้าเล่นด่านผังงาน)

- ใช้ hook แทนการ fetch เอง
- แสดงโพเดียม 1-3 พร้อมรูป แถวที่เหลือแสดง `#อันดับ`
- **เพิ่มการไฮไลต์แถวของตัวเอง** ซึ่งเดิมไม่มีเลย เทียบด้วย `my_user_id`
- ถ้าเปิดหน้านี้โดยไม่มี mission id ให้ขึ้นข้อความบอกทาง ไม่ใช่สปินเนอร์ค้าง
  (ในทางปฏิบัติ component นี้ถูกเรนเดอร์ใต้ route `/mission/:id` เสมอ แต่ไม่ควร
  พึ่งเงื่อนไขที่บังคับจากภายนอกอย่างเดียว)

`frontend/src/components/mcq/MCQLeaderboard.tsx` (แถบเข้มข้างจอทำข้อสอบ)

- ใช้ hook แทนการ fetch เอง
- โครงเดิมทั้งหมดคงไว้ รวมทั้งป้าย "อัปเดตแล้ว" และข้อความท้ายกล่อง

แถบควบคุมท้ายกล่องของทั้งสองหน้า เหมือนหอเกียรติยศ 3D

- ปุ่มก่อนหน้า/ถัดไป ปิดการใช้งานที่หน้าแรกและหน้าสุดท้าย
- ป้ายบอกช่วง เช่น "อันดับ 4–13 จาก 25"
- ปุ่ม "ไปที่อันดับของฉัน (#16)" แสดงเมื่อ `my_page` ไม่ใช่หน้าที่เปิดอยู่
- ถ้ามีคนไม่เกิน 3 คน (`total_pages` เป็น 1 และไม่มีแถวนอกโพเดียม) ไม่ต้องแสดง
  แถบควบคุมเลย

## การจัดการข้อผิดพลาด

- ดึงข้อมูลไม่สำเร็จ: คงข้อมูลเดิมที่แสดงอยู่ไว้ ไม่ล้างเป็นตารางว่าง เขียน log
  ไว้ที่ console เหมือนของเดิม การดึงรอบถัดไปจะกู้เอง
- โหลดครั้งแรกไม่สำเร็จ: hook คืน `loadFailed` เป็น true หน้าเว็บแสดง
  `โหลดอันดับไม่สำเร็จ กำลังลองใหม่อัตโนมัติ` แทนข้อความว่ายังไม่มีใครได้คะแนน
- ตอบ 400 เพราะไม่มีขอบเขต: แสดงข้อความบอกทาง ไม่ใช่สปินเนอร์
- ยังไม่มีใครลงมือทำด่าน (`total` เป็น 0): คงข้อความเดิมของแต่ละหน้า

## เทสต์

### Backend

สร้าง `backend/test_mission_leaderboard_pagination.py`

- รูปทรง response มีคีย์ครบตามที่ระบุไว้
- ขอบ 13 คน (หน้าเดียว) กับ 14 คน (สองหน้า)

- คนที่ลงทะเบียนในรายวิชาแต่ยังไม่ลงมือทำด่าน ต้องไม่อยู่ในตาราง
- `avatar_url` มาเฉพาะใน `top3` ส่วนใน `rows` เป็น `null` เสมอ
- เรียกโดยไม่ระบุขอบเขตได้ 400

สร้าง `frontend/tests/leaderboard-range.test.mjs` ทดสอบ `rankRangeLabel`

### ตรวจด้วยมือ

เปิดเบราว์เซอร์จริงทั้งสองหน้า ตรวจว่าเปลี่ยนหน้าได้ ปุ่มไปที่อันดับของตัวเอง
พาไปหน้าที่ถูกและไฮไลต์ถูกคน การรีเฟรชจาก socket ไม่เด้งกลับหน้า 1 และวัดขนาด
payload ก่อนกับหลังมาเทียบกัน

## ผลข้างเคียงที่ต้องรู้

response เปลี่ยนรูปทรงจาก array เป็น object ถ้าอัปเดตเซิร์ฟเวอร์โรงเรียนแบบ
backend ใหม่คู่กับ frontend เก่า ตารางอันดับจะว่างเปล่า จึงต้องอัปเดตทั้งสอง image
พร้อมกัน ซึ่งคำสั่ง `docker compose ... up -d` ที่ใช้อยู่ทำให้อยู่แล้ว
